# Quick Task 260318-r63: Add Multi-Column Btree Indexes to Composite PK Tables — Summary

**One-liner:** 19 composite PK tables gained multi-column btree indexes and 11 reducer/helper files migrated from O(n) filter+find scans to O(log n) `.filter([val1, val2])[0]` lookups, with 32/32 integration tests verified passing.

## What Was Done

### Task 1: Table Index Additions

Added one multi-column btree index to each of 19 composite PK tables. Each index accessor follows the `by_{col1}_and_{col2}` naming convention and the columns array matches the PK column order exactly.

| Table | Accessor | Columns |
|-------|----------|---------|
| calendarEventInvite | `by_event_and_invitee` | `[eventId, inviteeUserId]` |
| characterStats | `by_user_and_character` | `[userId, characterName]` |
| costSetDraftCharacter | `by_set_character_and_mode` | `[costSetId, characterName, gameMode]` |
| costSetDraftLightcone | `by_set_lightcone_and_mode` | `[costSetId, lightconeName, gameMode]` |
| costSetDraftSynergy | `by_set_source_target_and_mode` | `[costSetId, sourceName, targetName, gameMode]` |
| groupStanding | `by_tournament_group_and_team` | `[tournamentId, groupId, participantTeamId]` |
| hsrAccountCharacter | `by_account_and_character` | `[hsrAccountId, characterName]` |
| hsrAccountLightcone | `by_account_and_lightcone` | `[hsrAccountId, lightconeName]` |
| hsrCharacterArchetype | `by_character_and_archetype` | `[characterName, archetypeId]` |
| hsrCharacterCost | `by_character_mode_and_set` | `[characterName, gameMode, costSetId]` |
| hsrLightconeCost | `by_lightcone_mode_and_set` | `[lightconeName, gameMode, costSetId]` |
| lobbyMember | `by_lobby_and_user` | `[lobbyId, userId]` |
| matchResultGame | `by_result_and_game` | `[matchResultId, gameNumber]` |
| matchResultParticipant | `by_result_and_user` | `[matchResultId, userId]` |
| mmrRating | `by_user_and_mode` | `[userId, gameMode]` |
| savedCalendar | `by_user_and_target` | `[userId, targetUserId]` |
| teamMember | `by_team_and_user` | `[teamId, userId]` |
| tournamentAssistant | `by_tournament_and_user` | `[tournamentId, userId]` |
| tournamentTeamRequest | `by_team_and_user` | `[teamId, userId]` |

TournamentParticipant was excluded — already had `by_tournament_and_user` from Phase 3.

### Task 2: Reducer/Helper Migration

Replaced all `filter(val).find(r => r.col2 === val2)` patterns with `filter([val1, val2])[0]` across 11 files:

- **roster.ts** — 2 occurrences (batch_upsert_characters, migrate_roster)
- **rosterAdmin.ts** — 6 occurrences (upsert/remove characters, assign/remove archetypes)
- **tournamentRegistration.ts** — 5 occurrences (register, withdraw, approve, waitlist_promote)
- **tournamentTeams.ts** — 7 occurrences (create team, request join, accept/reject request, leave team)
- **tournamentAdmin.ts** — 3 occurrences (dq_participant, assign/remove assistant)
- **refereeManagement.ts** — 7 occurrences (transfer/reclaim referee, set/remove coach)
- **matchResultSubmission.ts** — 2 occurrences (lobby member + assistant lookups)
- **bracketAdvancement.ts** — 1 occurrence (winner participant lookup)
- **cursor.ts** — 1 occurrence (lobby membership check)
- **admin.ts** — 2 occurrences (admin_delete_row for HsrCharacterArchetype and LobbyMember)
- **tournamentHelpers.ts** — 1 occurrence (ensureTournamentAccess assistant check)

Three patterns were intentionally skipped (not composite PK lookups):
- `HsrAccount.user_id.filter().find(a => a.isActive)` — boolean column filter
- `TournamentTeam.captain_user_id.filter().find(team => team.tournamentId === X)` — autoInc PK table
- Two `filter().filter()` bulk-fetch patterns in tournamentTeams.ts
