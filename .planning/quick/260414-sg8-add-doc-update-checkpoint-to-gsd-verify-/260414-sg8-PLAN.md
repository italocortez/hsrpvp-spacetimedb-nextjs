<feature_detection_approach>
The shell one-liner embedded in the workflow is:

```bash
# PHASE_BASE = commit before first commit of current phase (derived from STATE.md or `git log` phase tag)
# Fallback: merge-base with main if no phase tag available
CHANGED_PATHS=$(git diff --name-only "${PHASE_BASE}"..HEAD)

# Collect every docs/ feature dir whose name (or a close match) appears anywhere in CHANGED_PATHS
TOUCHED_FEATURES=()
for feat_dir in docs/*/; do
  feat=$(basename "$feat_dir")
  # Match 1: backend path contains the feature name as a path segment or kebab-to-camel/snake variant
  # Match 2: any changed path under docs/$feat/ itself (doc was edited — still prompt)
  if echo "$CHANGED_PATHS" | grep -qiE "(^|/)(${feat}|$(echo "$feat" | tr -d '-'))($|/|\\.)"; then
    TOUCHED_FEATURES+=("$feat")
  fi
done
```

Constraints:
- No AST parsing, no timestamp heuristics — path presence only (per rejected alternatives).
- Empty match → checkpoint immediately satisfied, workflow continues.
- Prompt-level transparency: show the user the matched paths so they can override (force-add a feature the heuristic missed, or skip a false positive).
</feature_detection_approach>
