# Quick Task 260414-sg8: Add doc-update checkpoint to gsd-verify-work

**One-liner:** Mandatory `doc_update_checkpoint` step added to `/gsd-verify-work` zero-issues branch — detects touched `docs/{feature}/` dirs via git diff, prompts per feature for architecture.md/contract.md/both/skip, and blocks phase transition until every feature is answered.

## What Was Built

### Task 1 — verify-work.md (commit d169f3e)

Two additions to `.claude/get-shit-done/workflows/verify-work.md`:

1. **Invocation line** in `complete_session` zero-issues branch, after the security gate decision and before `transition.md` is read:
   > `Run doc_update_checkpoint (defined below) before proceeding. The checkpoint must complete (all touched features answered) before transition.md is invoked.`

2. **Full step definition** `<step name="doc_update_checkpoint">` inserted between `scan_phase_artifacts` and `diagnose_issues`. The step:
   - Resolves phase commit range via `git log --grep` of phase-tagged commits; falls back to `git merge-base HEAD main` with a visible warning
   - Detects touched features by looping over `docs/*/` dir names and matching against `git diff --name-only` output (hyphen-stripped fuzzy variant included)
   - Silently clears when no features match
   - Presents a four-option prompt per feature: `[a]` both, `[b]` architecture only, `[c]` contract only, `[d]` skip with required reason
   - Options a/b/c: reads diff + current doc, proposes edits, applies on approval, commits as `docs(phase-N): sync {feature}`
   - Option d: appends YAML skip record to phase UAT.md under `## Doc Update Skips`, commits as `test(N): record doc skip — {feature}`
   - Prints a summary table after all features are answered, then falls through to transition.md
   - Honors TEXT_MODE flag for non-AskUserQuestion runtimes

3. **success_criteria** gains: `[ ] Doc update checkpoint answered for every touched feature before phase marked complete (zero-issues branch only)`
