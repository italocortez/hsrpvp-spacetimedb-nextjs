<!-- Bisect command template (per D-01) -->

Bisect workflow for file F that fails in full suite but passes in isolation:

Step 1 — Confirm isolated pass:
```
npx vitest run --config test/vitest.integration.config.ts test/backend/<domain>/F.test.ts
```
Must exit 0. If file fails in isolation too, it's a per-file bug — fix it directly (not a pollution issue).

Step 2 — Run full suite with verbose reporter to get exact execution order:
```
npm run test:all -- --reporter=verbose 2>&1 | tee /tmp/full-run.log
grep -E "(RUN|FAIL|PASS) .*\.test\.ts" /tmp/full-run.log
```

Step 3 — Identify files that run BEFORE F in the vitest order. Call this set `predecessors`.

Step 4 — Binary search. Pick the middle half of predecessors. Run with explicit file list:
```
npx vitest run --config test/vitest.integration.config.ts \
  test/backend/<half1>/*.test.ts test/backend/<half2>/*.test.ts test/backend/<domain>/F.test.ts
```
- If F still fails, polluter is in this half → recurse into first half.
- If F passes, polluter is in the other half → recurse into second half.

Step 5 — Converge on a single polluter file P.

Step 6 — Classify the interaction:
- If P leaks resources that F's assertions measure → missing-cleanup in P (already should have been caught by Plan 03; if surfaces here, update Plan 03's file list)
- If F has absolute count assertion (`toBe(0)`, `toHaveLength(N)`) against a table P populates → absolute-count in F
- If F expects artifact P creates → ordering dependency; make F self-seed per D-04
- If F references a renamed column/enum P created → stale-assertion in F

const awards = [...h.conn.db.UserAchievement.iter()].filter(a => a.userId === user.userId);
