| Option | Description | Selected |

**User's choice:** Bisect suspect pairs
**Follow-up clarification:** Bisect mechanic scoped to failure-driven — run full suite, for each failing file run it alone to confirm passes, then binary-search prepended files to find polluter. Not O(N²) pairwise.
**Notes:** User wants precision over predictability. Bisect targets only actual failures, keeping scope bounded.

## Additional User-Driven Decisions (free text)

### Seed Baseline (D-09) and DB Reset (D-10)

**User's input:** *"The only data that should be seeded for everyone is the character and lightcone data that lives in test/data/*.json. These files are not insert as is, they use the admin bulk upsert but they only have to be inserted once. For SpacetimeDb cleanup just do a cancel on ident (I guess this is a clear-database)."*

**Captured as:**
- D-09: Global seed = static game data only (characters/lightcones from test/data/*.json via admin_bulk_upsert, idempotent). All dynamic data per-file.
- D-10: DB reset via `spacetime publish --clear-database` — SpacetimeDB's mechanism for full DB-wide cleanup. Not per-row teardown.

### Minimum-Data Principle (D-11)

**User's input:** *"While fixing the test ask your question 'what is the minimum amount of data that I need to test this scenario?' and use that; some of the tests are inserting too many entities for no real gain, check that carefully."*

**Captured as:**
- D-11: When fixing any test, ask what's the minimum data needed for the scenario. Trim over-inserting tests aggressively during the audit.

### Server Identity Singleton (D-12)

**User's input:** *"The server identity needs to only be inserted ONCE. Everyone uses that one and should not cause any conflict between tests as it is a read only env variable (through .env or .env.local)."*

**Captured as:**
- D-12: Server identity inserted once via register_server during bootstrap; SPACETIMEDB_SERVER_TOKEN read-only from .env.local. All harnesses share it. Never per-file.
