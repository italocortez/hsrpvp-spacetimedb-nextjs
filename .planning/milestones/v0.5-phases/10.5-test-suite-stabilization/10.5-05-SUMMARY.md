## Issues Encountered

- **Bash heredoc limits on `grep -c` output in batch commands:** When running multiple grep -c counts chained with `&&` in a single Bash call, execution stopped at the third grep. Workaround: split into separate Grep tool calls (each counted correctly).

## Phase 10.5 Closing Reflection

### What Phase 10.5 Accomplished

**The primary question — "why did Phase 10.4's exit tests fail cross-file?" — was answered empirically.** The research hypothesis (pollution-driven, not bug/rename-driven) was validated in Plan 01's fresh-DB baseline: 673/673 passed with no fixes applied. Plans 02+03 then applied the known-good mechanical fixes (helper extraction + afterAll cleanup contract). Plan 04's bisect exit-condition triggered with zero failures on the populated-DB run, confirming the fixes were comprehensive. Plan 05 closed the phase with documentation.

**Three durable patterns emerged:**

1. **`openedResourceIds[] → afterAll` cleanup contract** is the mandatory pattern for any test file creating dynamic resources. 13 files adopted it; calendar_event/achievement leaks went to STABLE zero.
2. **Union-superset helper defaults** caught silent drift. 100 typecheck errors resolved as a byproduct of helper extraction — tests were running on JS-not-TS so the drift was invisible until helpers forced type alignment.
3. **Pollution-induction via repeat test:all runs** is the correct methodology (NOT synthetic row corruption) because it matches the production failure pattern exactly.

**What the audit revealed about the existing suite:** It was better than expected. 0 failures on fresh DB meant the cross-file dependencies were more about cleanup hygiene than actual bugs. Phases 10.1-10.4 rename churn was fully absorbed by the existing tests — no stale assertions required code changes.
