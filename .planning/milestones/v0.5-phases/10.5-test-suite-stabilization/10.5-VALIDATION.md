# Phase 10.5 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
>
> **Special note:** This phase's deliverable IS the test suite itself. Validation
> for this phase = verifying that the test suite (which validates all other phases)
> now runs green end-to-end. The "test of the test" is running `npm run test:all`.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest 4.1.x |
| **Config file** | `test/vitest.integration.config.ts`, `test/vitest.config.ts` |
| **Quick run command** | `npm test` (unit tests only, ~5-15s) |
| **Full suite command** | `npm run test:all` (unit + integration, runtime TBD in Plan 01) |
| **Per-file runner** | `npx vitest run --config test/vitest.integration.config.ts <path>` |
| **Estimated runtime** | ~TBD — measured as Plan 01 deliverable |

---

## Sampling Rate

- **After every task commit:** Run affected test file(s) in isolation (e.g. `npx vitest run <file>`)
- **After every plan wave:** Run `npm run test:all` and verify same file count passes (no regression)
- **Before `/gsd:verify-work`:** Full suite must be green end-to-end on fresh `--clear-database` + bootstrap
- **Max feedback latency:** per-file ~5-30s; full suite ~TBD
