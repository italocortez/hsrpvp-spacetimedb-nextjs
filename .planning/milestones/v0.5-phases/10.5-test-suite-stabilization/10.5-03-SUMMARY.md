## Decisions Made

- **cleanupTournament semantic:** Tournament rows PERSIST after cancelTournament (audit trail per D-21, D-22). The cleanup contract's goal is NOT zero rows but rather transitioning dynamic resources to terminal states (Cancelled) so subsequent test runs don't inherit active/dangling state.
- **AwaitingResult lobby handling:** For tournament-mmr and bracket-advancement (both exercise Ranked/MMR flows that can leave lobbies in AwaitingResult), the afterAll tries `admin.call.adminVoidMatch({ lobbyId })` FIRST (swallowed), then `toUser.call.closeLobby({ lobbyId })` as fallback. Dual-attempt covers both possible lobby states.
- **Idempotent safety-net philosophy:** chat-messages and lobby-lifecycle already close lobbies inline mid-test. Per plan D-08, we ADD afterAll cleanup but DO NOT REMOVE the inline calls. cleanupLobby swallows "already closed" errors, so no harm. This converts YELLOW classification (leaks on assertion failure) to GREEN (guaranteed cleanup).
- **Completed-tournament rows persist:** MMR tests (tournament-mmr, bracket-advancement) advance tournaments to Completed stage as part of scenarios. cancelTournament is rejected on terminal states — these rows cannot be cleaned by cleanupTournament. They persist until full `--delete-data=always` reset. Documented in AUDIT.md.
- **Per-file verification over per-commit full-suite:** Plan 02 established 55min × N commits is prohibitive (4+ hours). Same approach here: run each modified file in isolation after commit (typical ~30s-2min), single full-suite regression run at end.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added `openedLobbyIds[]` tracking to tournament-mmr / bracket-advancement (Pitfall 3)**
- **Found during:** Task 1 (tournament-mmr.test.ts) + Task 2 (bracket-advancement.test.ts)
- **Issue:** Both files run Ranked MMR flows which transition lobbies to AwaitingResult after score submission. Per Pitfall 3 in research, AwaitingResult lobbies cannot be closed via close_lobby — they require admin_void_match. Original plan's tournament-mmr special case mentioned "admin_void_match if AwaitingResult state is reached" but didn't specify tracking lobbyIds; the plan's tournament cleanup pattern alone wouldn't release the lobby.
- **Fix:** Added `openedLobbyIds: number[]` tracking to both files. In afterAll, try admin.adminVoidMatch() first (swallow error), then toUser.closeLobby() as fallback (swallow error), THEN cleanupTournament the tournaments.
- **Files modified:** tournament-mmr.test.ts (commit 3484461), bracket-advancement.test.ts (commit 8dc9895)
- **Verification:** Both files pass in isolation; dual-attempt fallback handles both AwaitingResult and completed-lobby states.

**2. [Rule 3 - Blocking] Per-file verification substituted for per-commit full-suite run**
- **Found during:** Task 1 start (time budget analysis)
- **Issue:** Plan specified running `npm run test:all` (55 min) after each of 13 per-file commits = 12+ hours of test wall-clock. Exceeds reasonable autonomous execution window.
- **Fix:** Substituted per-file isolation runs (typical 30s-2min each) after each commit for targeted verification. Ran ONE full `npm run test:all` regression check on fresh DB after all 13 commits landed.
- **Files modified:** None (process deviation, no code change)
- **Verification:** All 13 isolation runs passed; final full-suite run 673/673 pass in 55min.
