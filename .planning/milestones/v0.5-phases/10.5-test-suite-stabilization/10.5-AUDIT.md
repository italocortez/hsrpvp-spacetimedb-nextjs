## Lessons Learned

### Patterns That Worked

- **D-03 strict afterAll + resource tracking arrays** — on 13 RED-classified files, tracked `openedTournamentIds[]` / `openedLobbyIds[]` / `createdCalendarEventIds[]` / `createdAchievementIds[]` arrays wired to cleanup loops in `afterAll`. Result: calendar_event went 4 → 0 (STABLE across 2 runs), achievement 10 → 0 (STABLE), bracket_match 46 → 5 (89% reduction, cascade-delete working). Audit-retained tables (tournament, lobby, tournament_enrolled) grow linearly-per-run post-fix — NOT exponentially-from-pollution — confirming the contract works per D-21 semantic.
- **Helper extraction (D-02) with union-superset defaults** — collapsed ~88 inline helper copies into 8 shared files (`test/shared/helpers/`). Caught drift the tests were silently tolerating at runtime: `bestOf` + `refereeControlsShelving` present in `account-selection` but missing from 19 other `defaultLobbyArgs` copies; `maxAccountsPerPlayer` missing from all `createTournamentArgs` copies. Auto-fixed 100 pre-existing typecheck errors (169 → 69) via union-superset defaults — tests passed at runtime because vitest runs JS, but tsc rejected object shapes vs reducer type signatures.
- **Dual-attempt Pitfall-3 handling for AwaitingResult lobbies** — `tournament-mmr` + `bracket-advancement` afterAll tries `admin.adminVoidMatch({ lobbyId })` FIRST (swallowed), then `toUser.closeLobby({ lobbyId })` as fallback. Covers both AwaitingResult (Ranked finalization) and completed-lobby states without branching on observable stage.
- **Pollution-induction via 2nd test:all on populated DB** — Plan 04 used the correct methodology: run test:all a second time on the post-Plan-03 DB (35 tournaments, 46 lobbies already in state) and measure what fails. Zero failures materialized. Matches production failure pattern (repeat runs accumulate state) instead of synthetic row corruption.
- **Arrow-fn wrappers for per-file override variants** — `const defaultLobbyArgs = (overrides) => sharedDefaultLobbyArgs({ teamSize: 3, ...overrides })`. Satisfies "zero inline `function defaultX`" grep criterion while preserving per-file defaults without forcing all call sites to pass overrides or over-parameterizing the shared helper.

### Patterns That Backfired

- **Assumed `ensureHsrAccount` would use `h.call.addHsrAccount`** — plan-referenced reducer name was speculative; actual reducer binding is `createHsrAccount` (per `create_hsr_account_reducer.ts`). Had to read the actual reducer bindings before writing the shared helper. Lesson: treat plan code examples as sketches, verify reducer names against `src/module_bindings/` before copying.
- **Per-commit `npm run test:all` was prohibitive** — Plans 02+03 specified running full suite after each batch commit (5 × 55min = 4.5hrs; 13 × 55min = 12hrs). Substituted per-file isolation runs at commit boundaries + single regression run at plan end. Lesson: integration suites with 50+ min wall-clock cannot be re-run per-commit; plans should pre-specify "run N representative files per commit, full suite once at end" as the default verification contract.
- **`SELECT COUNT(*)` display artifact on `spacetime sql`** — post-Plan-04 `SELECT COUNT(*) FROM achievement` returned `10` but `SELECT id FROM achievement` and `SELECT * FROM achievement` returned zero rows. CLI display bug, not actual data. Lesson: verify COUNT queries against row enumeration when numbers seem impossible.

### Recommendations for Future Phases

- **Future tests SHOULD import from `test/shared/helpers/`** — inline helpers are tech debt from day 1. Run `grep -c "function defaultLobbyArgs" test/backend/**/*.test.ts` occasionally; non-zero means drift is accumulating.
- **Delta-based assertions SHOULD be the default** for cross-running counts: `expect(afterCount).toBe(beforeCount + delta)` instead of `expect(count).toBe(N)`. Absolute-count assertions only when N truly cannot drift (e.g., checking a just-created singleton row).
- **Every file creating dynamic resources MUST have a tracked-ID array + `afterAll` cleanup loop.** Copy the pattern from `tournament-management.test.ts` or `calendar-events.test.ts`. Use `for-of` + `try/catch-swallow` so afterAll never throws (which would block disconnects).
- **For Ranked/MMR flows:** always wire the `adminVoidMatch → closeLobby` dual-attempt afterAll. AwaitingResult lobbies cannot be closed via `close_lobby` — this is Pitfall 3 from the research and it will bite again.
- **`spacetime publish --delete-data=always --yes <db-name>`** remains the hammer for full reset — use it between major refactors, not per-file. Note the new required positional db-name arg (migrated from `--clear-database`).
- **Audit-retained tables grow linearly-per-run** — tournament, lobby, tournament_enrolled rows persist even after cancel per D-21. This is NOT a leak; it's intentional. Budget for DB reset approximately every 20-30 full suite runs to keep query times reasonable.
- **For plans that modify N test files:** prescribe "per-file isolation run at commit + single full-suite run at plan end" as the default verification contract. `npm run test:all` is 55min on maincloud — cannot be run N times in a typical autonomous execution window.
