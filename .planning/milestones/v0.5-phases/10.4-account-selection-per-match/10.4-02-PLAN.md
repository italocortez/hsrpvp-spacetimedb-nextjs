    **1. Refactor `validateCharacterOwnership` in ownershipValidation.ts** (per D-12, D-13, D-14):

    Replace the ENTIRE function body. The new logic checks characters from LobbyMemberAccount entries only (both tournament and non-tournament paths use the same code path per D-14):

    ```typescript
    export function validateCharacterOwnership(
        ctx: any,
        userId: number,
        characterName: string,
        lobbyId: number
    ): { valid: boolean; reason?: string } {
        // Look up the Lobby
        const lobby = ctx.db.Lobby.id.find(lobbyId);
        if (!lobby || !lobby.requireOwnership) {
            return { valid: true };
        }

        // D-14: Check characters from LobbyMemberAccount entries only
        const selectedAccounts = [...ctx.db.LobbyMemberAccount.by_lobby_and_user.filter([lobbyId, userId])];

        if (selectedAccounts.length === 0) {
            // No accounts selected — ownership cannot be validated
            return { valid: false, reason: 'No account selected for this match.' };
        }

        // D-12: Union of characters across all selected accounts
        for (const lma of selectedAccounts) {
            const character = [...ctx.db.HsrAccountCharacter.by_account_and_character.filter([lma.hsrAccountId, characterName])][0];
            if (character) {
                return { valid: true };
            }
        }

        return { valid: false, reason: 'You do not own this character on any selected account.' };
    }
    ```

    This replaces the old tournament-path (which checked ALL TournamentPlayerAccount entries) and non-tournament-path (which checked only the active account). Both now use LobbyMemberAccount. This works because:
    - Tournament lobbies: LobbyMemberAccount rows are validated against TPA at selection time (D-05)
    - Non-tournament lobbies: LobbyMemberAccount row is the active account (D-04, D-07)

    D-12 note: "If a character exists on multiple accounts, highest eidolon level wins" — this is relevant for draft pool display, NOT for ownership validation. Ownership just needs to find the character on ANY selected account. The eidolon-level merge is a view concern (handled in Plan 03).
