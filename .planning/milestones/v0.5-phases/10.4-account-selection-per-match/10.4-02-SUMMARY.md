# Phase 10.4 Plan 02: LobbyMemberAccount Lifecycle Integration Summary

**One-liner:** LobbyMemberAccount wired into all lifecycle touchpoints — auto-created at join (with TPA validation and stand-in snapshotting), cascade-deleted at leave/GC, deletion-guarded in roster reducers, and used exclusively for ownership validation and start_draft enforcement.

## What Was Built

### Task 1: Lobby Lifecycle Wiring

**join_lobby (D-04, D-09):** After inserting LobbyMember, auto-creates a `LobbyMemberAccount` row:
- Non-tournament lobbies: uses player's active HsrAccount directly
- Tournament lobbies: validates active account against TPA; falls back to first locked account if active isn't locked; skips if no TPA entries (stand-in not yet approved)
- D-26: Detects stand-ins via `TournamentStandIn.by_match_and_user`; if found and no TPA entries yet, snapshots all user accounts into TPA then creates LMA row

**leave_lobby (D-29):** Added `LobbyMemberAccount.by_lobby_and_user.filter` cleanup in all 3 exit paths:
- Spectator/Coach active stage clean leave
- Player active stage leave (voluntarilyLeft path) 
- Waiting/AwaitingResult/Finished normal leave path

**hardDeleteLobby cascade (D-28):** Added step 1.5 — deletes all `LobbyMemberAccount.lobby_id.filter(lobbyId)` rows before LobbyMember deletion. Updated cascade comment in file header.

**delete_hsr_account and admin_delete_hsr_account (D-24, D-25):** Both blocked with identical guards:
1. `LobbyMemberAccount.by_account.filter` — throws if any active lobby references the account
2. `TournamentPlayerAccount.by_user.filter` + tournament stage check — throws if locked in active (non-Completed/non-Cancelled) tournament

### Task 2: Ownership Validation Refactor

**validateCharacterOwnership (D-14):** Complete rewrite. Replaced two separate code paths (tournament via TPA, non-tournament via active account) with a single unified path: `LobbyMemberAccount.by_lobby_and_user.filter` for both. Character found on any selected account returns `{ valid: true }`. Empty selection returns actionable error "No account selected for this match."

**start_draft enforcement gate (D-08):** Added `needsAccountEnforcement` check — triggers for `Ranked` match type or tournament lobbies with `countTowardsMmr=true`. All `playersOnly` members must have at least one LMA row or draft is blocked.

**autoRandomPick refactor (D-12):** Migrated from `HsrAccount.user_id.filter -> activeAccount` to `LobbyMemberAccount.by_lobby_and_user.filter` + union of characters across all selected accounts. Consistent with validateCharacterOwnership approach.

## Deviations from Plan

None — plan executed exactly as written.

One minor structural decision: the stand-in TPA snapshot block checks `lobby.bracketMatchId` being truthy before attempting `TournamentStandIn.by_match_and_user.filter`. This guards against tournament lobbies that have `tournamentId` but no `bracketMatchId` (e.g., lobby not yet assigned to a bracket match). The plan's pseudocode used `lobby.bracketMatchId ?? 0` which would query with 0 — the guard is slightly tighter.
