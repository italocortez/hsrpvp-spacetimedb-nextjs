## Decisions Made

- LobbyMemberAccount has no audit columns — ephemeral join table that doesn't need history tracking
- Used 3 btree indexes from the start: lobby_id (needed for hardDeleteLobby cascade in Plan 02), by_lobby_and_user (main query path), by_account (reverse lookup and deletion guard)
- Tournament path is additive (multiple accounts up to maxAccountsPerPlayer); non-tournament path is replace (always exactly one account, no Lobby.maxAccountsPerPlayer column needed)
- Kept the `lobby_id` single-column btree index explicitly — Plan 02 will iterate by lobbyId alone when deleting LobbyMemberAccount rows in hardDeleteLobby
