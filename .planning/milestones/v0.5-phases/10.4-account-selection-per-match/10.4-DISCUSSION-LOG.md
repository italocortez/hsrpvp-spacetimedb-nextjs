## Account Storage Model

| Option | Description | Selected |
|--------|-------------|----------|
| Array column | t.array(t.u32()) on LobbyMember. Precedent in MatchSession.draftSequence. | |
| Join table | LobbyMemberAccount(lobbyId, userId, hsrAccountId). Composite PK pattern. | X |
| Single + overflow | Single column for common case, overflow table for multi-account. | |

**User's choice:** Join table (LobbyMemberAccount)
**Notes:** Decisive factor was anonymous mode safety. LobbyMember is public and frequently subscribed -- anything embedded leaks to all lobby participants. Non-public join table keeps account selection server-side only. Also better for bandwidth (account data decoupled from frequent LobbyMember updates) and queryability (btree indexes enable reverse lookups).

## Selection Timing & Flow

| Option | Description | Selected |
|--------|-------------|----------|
| Auto at join + change later | join_lobby auto-inserts row with active account. select_match_account to change. | X |
| Explicit reducer only | No auto-populate. Player must call select_match_account before draft. | |

**User's choice:** Auto at join + change later
**Notes:** User specified: "Users have a default active account, when they join a lobby, by default they use that one. Inside the lobby during waiting stage they have the ability to change which one they are going to use." Also confirmed BetweenGames stage allowed for best-of-N series.

**Follow-up: Fallback when active account not locked for tournament**
User asked to consider what's easiest. Agreed on: auto-select first locked TournamentPlayerAccount entry as fallback.

**Follow-up: Ranked non-tournament lobbies**
User raised: "what about Ranked matches that are non tournaments?" Led to renaming reducer from `select_tournament_account` to `select_match_account` (unified for tournament and non-tournament). Enforcement at start_draft for ranked/MMR-tournament.

## Edge Cases (Critical Review)

**Shelved stage:** Not included in select_match_account stage guard. Unshelving returns to BetweenGames where changes are allowed. Less redundant for frontend.

**LobbyMemberAccount on leave:** Delete immediately (no preservation). Account selection is ephemeral.

**Casual account limit:** select_match_account replaces (not adds) for non-tournament lobbies. Max 1 enforced by behavior.

**Account switching between games:** Fresh draft each game (Phase 10.1 D-02 reset model). No carry-over from previous game's picks.
