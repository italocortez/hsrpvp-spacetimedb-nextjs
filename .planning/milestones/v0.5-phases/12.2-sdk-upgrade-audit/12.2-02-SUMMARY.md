# Phase 12.2 Plan 02: Auth Flow Rework Summary

**Frontend auth reads from typed view_my_profile binding with User table fallback, confirmed reads disabled, reducer calls use .catch() error handling**

## Accomplishments
- `readProfileFromConnection` reads from `conn.db.view_my_profile.iter()` as primary source — private fields (discordId, discordUsername) now populated

## Decisions Made
- **SDK 2.1.0 _then() doesn't exist:** Reducer calls return `Promise<void>`. The `_then()` pattern from skill docs was stale for this SDK version. Used `.catch()` for network-level errors instead. Reducer business logic failures are communicated via subscription callbacks (row doesn't appear).
- **Kept User table subscription:** `SELECT * FROM user` subscription preserved for 3-fallback resolution strategies that require PK/username index lookups (views have no indexes).

- **Fix:** Replaced all 3 `_then()` calls with `.catch()` pattern
