### Why the integration suite cannot run from this worktree

1. **No `.env.local` in the worktree.** `test/global-setup.ts:55-59` requires `PUBLIC_SPACETIMEDB_DB_NAME` from `.env.local` to safely clear the test database before each run. The parallel-executor worktree is a fresh checkout that does NOT carry `.env.local`.

2. **CLAUDE.md forbids creating `.env.local`.** The project's git rules explicitly prohibit any agent from creating, editing, or committing `.env.local` — that file is only modified by `scripts/post-publish.ts --clear-database`.

3. **`SKIP_DB_CLEAR=1` bypass is unsafe cross-worktree.** Even if global setup is bypassed, the individual test harnesses still need `SPACETIMEDB_SERVER_TOKEN` which comes from `.env.local` via the same loader. And running tests from a sibling-worktree sandbox against the shared maincloud test DB would race with any concurrent executor or `/gsd-verify-work` session.

4. **Parent repo's `.env.local` exists but cannot be used** per the CLAUDE.md rule and sandbox isolation:
