<objective>
Add a tournament-stage ordering guard to `finalize_match_result` that rejects the reducer when the caller attempts to finalize a tournament-controlled match before the parent tournament has reached a terminal stage (`Completed` or `Cancelled`). The guard protects two properties in the same rule: (1) MMR batch processing — `process_tournament_mmr` must run before `runFinalization` deletes MRP/MatchResultGame/lobby rows; (2) Bracket rollback capability — ephemeral match data must remain alive until the TO decides the tournament is done. The guard is unconditional: `countTowardsMmr` is NOT consulted, because the rollback property applies to casual tournaments too.

Purpose: Prevent an admin or TO from mid-tournament finalizing a single match and silently losing its MMR input (because `runFinalization` step 18 deletes the MRP rows `process_tournament_mmr` needs to read) or destroying the rollback window.

Output: `matchFinalization.ts` with a ~12-line guard block inserted between the existing `matchResult` lookup (line ~22) and the authority check (line ~30). No other file touched.
</objective>
