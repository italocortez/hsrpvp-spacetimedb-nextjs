<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → SpacetimeDB reducer (start_draft) | Authenticated caller invokes `start_draft`; module writes the MMR snapshot inside the same transaction — attacker cannot interleave a rating mutation mid-capture because reducers are transactional (SpacetimeDB Core Concept #1). |
| client → SpacetimeDB reducer (timer_expiry_classic) | Server-scheduled reducer; no direct client invocation. Auto-pick pool construction is server-authoritative. |
| SpacetimeDB server → subscribed clients | `MatchResultParticipant` is `public: true`; the new `accountRatingSnapshot` column ships to any client subscribed to the table while the row is alive. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12.3-01 | Tampering (data integrity) | `MatchResultParticipant.accountRatingSnapshot` at insert time in `start_draft` | mitigate | Snapshot is computed inside the same transactional reducer that inserts the MRP row. `ctx.db.HsrAccount.accountRating` cannot change between read and insert within a single reducer (Core Concept #1). The `max` across LMA rows eliminates any "swap to lower account before start_draft" gaming; the user's best account at capture time is what counts. |
| T-12.3-02 | Information Disclosure | Public MRP column exposes snapshot | accept | The snapshot is always the caller's own max rating. No cross-user information leakage — a user's own rating is already visible to them. Row subscription scope is unchanged from the existing `isCaptain`/`teamSide` columns. Egress cost = 1 f64 per player per live match (bounded per CLAUDE.md C7). |
| T-12.3-03 | Tampering (migration gap) | `timer_expiry_classic` reading `HsrAccount.isActive` for auto-pick pool | mitigate | Task 2 migrates the pool to `LobbyMemberAccount.by_lobby_and_user`, matching `validateCharacterOwnership` and the `start_draft` autoRandomPick validation block. Removes the last in-gameplay isActive read and prevents mid-match isActive toggle from altering the available pool for an auto-pick. |
| T-12.3-04 | Denial of Service | Over-fetching in snapshot computation | accept | Per-participant cost is `1 indexed LMA filter + up to maxAccountsPerPlayer HsrAccount.id.find lookups`.
