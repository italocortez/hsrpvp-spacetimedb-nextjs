## Corrections Made

### View Architecture — Column Projection
- **Original assumption:** Custom t.object() projected row types with subset of columns to reduce bandwidth
- **User correction:** Return full .rowType (all columns). The bandwidth win is row filtering (only my tournaments), not column reduction. TOs need every column since they tinker with settings and brackets.
- **Reason:** TOs actively manage their tournament data — they need full rows. The value proposition is seeing only your own tournament rows, not all TOs' data.

### view_tournament_dashboard — Aggregation
- **Original assumption:** Server-side aggregated counts (participant count, team count, bracket status breakdown) in one summary row per tournament
- **User correction:** Raw filtered rows — separate views returning full table rows scoped to TO's tournaments. Frontend builds the dashboard.
- **Reason:** Gives frontend full flexibility for v1 UI without backend changes. The backend's job is row filtering, the frontend's job is presentation.
