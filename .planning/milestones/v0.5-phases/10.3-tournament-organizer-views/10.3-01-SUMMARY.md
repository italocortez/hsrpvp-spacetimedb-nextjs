## Decisions Made
- `getMyTournamentIds` returns `{ userId, tournamentIds }` (not just the Set) — preserves `userId` for views that might need it without a redundant lookup
- `view_my_tournament_lobbies` uses direct `Lobby.tournament_id` btree (Lobby has this index), not navigation via BracketMatch
- `view_my_tournament_team_members` navigates via `TournamentTeam.tournament_id → TournamentTeamMember.team_id` because TournamentTeamMember has no single-column tournament_id index
- `view_my_tournament_match_results` navigates via `BracketMatch.tournament_id → MatchResultRecord.bracket_match_id` because MatchResultRecord has no tournament_id column (Phase 10.2 removal)
