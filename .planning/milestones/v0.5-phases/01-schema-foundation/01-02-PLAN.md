**Complete table specifications** (from 01-RESEARCH.md — use these EXACTLY):

**Phase 2 — Roster:**

`hsrAccount.ts`: id (u32, PK, autoInc), userId (u32), uid (string), displayLabel (string), isActive (bool), rosterVisibility (RosterVisibility enum), + audit. Indexes: `hsr_account_user_id` (userId), `hsr_account_uid` (uid).

`hsrAccountCharacter.ts`: accountId (u32), characterName (string), eidolonLevel (u8), + audit. Composite PK: ['accountId', 'characterName']. Indexes: `hsr_acc_char_account_id` (accountId).

`hsrAccountLightcone.ts`: accountId (u32), lightconeName (string), superimpositionLevel (u8), + audit. Composite PK: ['accountId', 'lightconeName']. Indexes: `hsr_acc_lc_account_id` (accountId).

**Phase 3 — Tournament:**

`tournament.ts`: id (u32, PK, autoInc), name (string), description (string), organizerId (u32), format (TournamentFormat), stage (TournamentStage), defaultGameMode (GameMode), maxParticipants (u32), isAnonymousDefault (bool), isAnonymousSpectators (bool), isOpenRoster (bool), disconnectPolicy (DisconnectPolicy), checkInEnabled (bool), checkInPerRound (bool), autoForfeitEnabled (bool), autoForfeitMinutes (u32), bracketRevealAt (timestamp, optional), grandFinalsAdvantage (bool), groupAssignmentMode (GroupAssignmentMode), groupAdvanceCount (u8), seasonId (u32, optional), countTowardsMmr (bool), defaultBestOf (u8), + audit. Indexes: `tournament_organizer` (organizerId), `tournament_stage` (stage).

`tournamentParticipant.ts`: tournamentId (u32), userId (u32), teamId (u32, optional), participantType (ParticipantType), status (ParticipantStatus), seedNumber (u32, optional), anonymousAlias (string, optional), + audit. Composite PK: ['tournamentId', 'userId']. Indexes: `tp_tournament_id` (tournamentId), `tp_user_id` (userId).

`tournamentAssistant.ts`: tournamentId (u32), userId (u32), canValidateResults (bool), canOverrideResults (bool), canDqParticipants (bool), canManageBracket (bool), canAssignSeeds (bool), + audit. Composite PK: ['tournamentId', 'userId']. Indexes: `ta_tournament_id` (tournamentId), `ta_user_id` (userId).

**Phase 3 — Teams:**

`team.ts`: id (u32, PK, autoInc), name (string, unique), ownerId (u32), isAdHoc (bool), tournamentId (u32, optional), + audit. Indexes: `team_owner` (ownerId).

`teamMember.ts`: teamId (u32), userId (u32), memberRole (TeamMemberRole), + audit. Composite PK: ['teamId', 'userId']. Indexes: `tm_team_id` (teamId), `tm_user_id` (userId).

`teamInvite.ts`: id (u32, PK, autoInc), teamId (u32), inviteeUserId (u32), inviterUserId (u32), isPending (bool), + audit. Indexes: `ti_team_id` (teamId), `ti_invitee_id` (inviteeUserId).

**Phase 4 — Bracket:**

`bracketMatch.ts`: id (u32, PK, autoInc), tournamentId (u32), roundNumber (u32), matchNumber (u32), isLosersBracket (bool), groupId (u32, optional), participant1Id (u32, optional), participant2Id (u32, optional), nextWinnerMatchId (u32, optional), nextLoserMatchId (u32, optional), bestOf (u8), gameMode (GameMode), winnerAdvantage (u8), scheduledAt (timestamp, optional), lobbyId (u32, optional), checkInRequired (bool), winnerId (u32, optional), resultStatus (MatchResultStatus), + audit. Indexes: `bm_tournament` (tournamentId), `bm_lobby` (lobbyId).

`groupStanding.ts`: tournamentId (u32), groupId (u32), participantUserId (u32), wins (u32), losses (u32), draws (u32), points (u32), + audit. Composite PK: ['tournamentId', 'groupId', 'participantUserId']. Indexes: `gs_tournament_group` (tournamentId).

**Phase 5 — Match Results & MMR:**

`matchResult.ts`: id (u32, PK, autoInc), bracketMatchId (u32, optional), lobbyId (u32), player1Id (u32), player2Id (u32), isTournamentMatch (bool), status (MatchResultStatus), winnerId (u32, optional), mmrProcessedAt (timestamp, optional), + audit. Indexes: `mr_lobby` (lobbyId), `mr_player1` (player1Id), `mr_player2` (player2Id).

`matchResultGame.ts`: matchResultId (u32), gameNumber (u8), gameMode (GameMode), player1ScreenshotUrl (string, optional), player2ScreenshotUrl (string, optional), player1CyclesUsed (u32, optional), player2CyclesUsed (u32, optional), player1Score (u64, optional), player2Score (u64, optional), player1Boss1Score (u64, optional), player1Boss2Score (u64, optional), player2Boss1Score (u64, optional), player2Boss2Score (u64, optional), winnerId (u32, optional), validationStatus (ValidationStatus), validatedById (u32, optional), + audit. Composite PK: ['matchResultId', 'gameNumber']. Indexes: `mrg_match_result` (matchResultId).

`mmrRating.ts`: userId (u32), gameMode (GameMode), rating (u32), matchesPlayed (u32), globalCompositeRating (u32, optional), seasonId (u32, optional), + audit. Composite PK: ['userId', 'gameMode']. Indexes: `mmr_user_id` (userId), `mmr_rating` (rating).

`mmrHistory.ts`: id (u32, PK, autoInc), userId (u32), gameMode (GameMode), matchResultId (u32), previousRating (u32), newRating (u32), delta (i32), seasonId (u32, optional), + audit. Indexes: `mh_user_id` (userId), `mh_match_result` (matchResultId).

**Phase 6 — Player Stats:**

`playerStats.ts`: userId (u32, PK), matchesPlayed (u32), wins (u32), losses (u32), draws (u32), matchesSpectated (u32), + audit. Indexes: `ps_wins` (wins).

`characterStats.ts`: userId (u32), characterName (string), wins (u32), losses (u32), matchesPlayed (u32), + audit. Composite PK: ['userId', 'characterName']. Indexes: `cs_user_id` (userId).

**Phase 7 — Achievements:**

`achievement.ts`: id (u32, PK, autoInc), name (string, unique), description (string), triggerType (AchievementTriggerType), rarity (AchievementRarity), isOneTime (bool), thresholdValue (u32, optional), characterName (string, optional), + audit.

`userAchievement.ts`: id (u32, PK, autoInc), userId (u32), achievementId (u32), awardedById (u32), isDisplayed (bool), + audit. Indexes: `ua_user_id` (userId), `ua_achievement_id` (achievementId).

**Phase 8 — Calendar:**

`availabilitySlot.ts`: id (u32, PK, autoInc), userId (u32), startAt (timestamp), endAt (timestamp), isRecurring (bool), recurrenceRule (RecurrenceRule from structs — use the struct type directly as a column), expiresAt (timestamp), + audit. Indexes: `avail_user_id` (userId), `avail_start_at` (startAt).

`savedCalendar.ts`: userId (u32), targetUserId (u32), isVisible (bool), + audit. Composite PK: ['userId', 'targetUserId']. Indexes: `sc_user_id` (userId).

`calendarEvent.ts`: id (u32, PK, autoInc), organizerId (u32), title (string), startAt (timestamp), endAt (timestamp), bracketMatchId (u32, optional), + audit. Indexes: `ce_organizer` (organizerId), `ce_start_at` (startAt).

`calendarEventInvite.ts`: eventId (u32), inviteeUserId (u32), isAccepted (bool, optional), + audit. Composite PK: ['eventId', 'inviteeUserId']. Indexes: `cei_event_id` (eventId), `cei_invitee_id` (inviteeUserId).

**Phase 9 — Chat:**

`chatMessage.ts`: id (u32, PK, autoInc), lobbyId (u32), senderUserId (u32), senderType (ChatSenderType), content (string), metadata (string, optional), anonymousLabel (string, optional), + audit. Indexes: `chat_lobby_id` (lobbyId).

For tables with composite primary keys, use the `primaryKey` option on the table() config, NOT on individual columns. For auto-inc tables, use `t.u32().primaryKey().autoInc()` on the id column.
