## Decisions Made

### D-02-01: accountSelection composite-PK SAME-SHAPE migrates via updateWithAudit-as-insert-payload
`accountSelection.ts` L110-115 does `.delete(existingMrp)` then `.insert({...existingMrp, changes, ...auditUpdate})`. Same-shape spread pattern identified as Plan 01 D-01-ADJUNCT. Since the destination is `.insert()` (composite PK has no direct update accessor), the `updateWithAudit` return type (`T & AuditFields`) is used as the insert payload. Dropped the outer `} as any);` cast — zero behavior change verified via garbage-collector test suite (accountSelection and lobby-gc share the MatchResultParticipant cleanup path).

### D-02-02: auth.ts display fields already use undefined (no null-bug fixup needed)
Unlike Plan 01's calendarEvents.ts (which had to convert `null` → `undefined` on 4 optional-column writes), auth.ts already used `undefined` for optional User columns (`displayedAchievementId`, `deletedAt`). Zero inline bug-fixes needed in Cluster B.

### D-02-03: Tagged-enum `as any` preserved at field level (D-16)
- `banAdmin.ts` L49 `banType: { tag: banTypeTag, value: {} } as any` — kept
- `adminMatchTools.ts` L92-94 `winnerTeamSide: … as any`, `status: { tag: 'Validated', value: {} } as any` — narrowed to field level (was outer `} as any);`)

These are SDK tagged-union friction out of scope for Phase 15.3 per CONTEXT.md D-03b (tracked as future follow-up phase).

### D-02-04: Scheduled-job inserts (IdentityGcJob, LobbyGcJob) NOT migrated
The `ScheduleAt.time(...)` inserts for self-requeue jobs at identityGc L111, L168 and lobbyGc L179, L228 are NOT audit-call sites — they don't include audit columns. Left untouched per plan scope.
