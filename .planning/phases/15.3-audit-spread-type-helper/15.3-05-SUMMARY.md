## Decisions Made

### D-05-01: Cluster E is pure P1/P2/SAME-SHAPE -- no P4 or P5 discovered
Plan_specific_guidance anticipated this: "Per research, this cluster should be pure P1/P2 (no P4/P5). If grep surfaces auditUpdate in a stats-style delete+insert-carry context, treat as P4 and KEEP primitive." No such context surfaced. All TournamentEnrolled composite-PK delete+re-insert sites use `...enrolled` spread (SAME-SHAPE). All TournamentAssistant and LobbyMember composite-PK sites use `...existing`/`...member` spread (SAME-SHAPE). None build explicit new-shape rows that would require the `auditUpdate` primitive (Pitfall 1).

### D-05-02: seriesManagement ChatMessage.insert sites NOT migrated
The 3 ChatMessage system-message inserts in seriesManagement.ts (advance_to_next_game L126-138, shelve_series L177-189, resume_series L248-260) use inline manual audit writes (`createdById: user.id`, `createdDate: ctx.timestamp`, etc.) with hardcoded `senderUserId: 0` and `senderType: { tag: 'System', value: {} }`. They do not call `auditInsert`. Per plan scope ("only explicit auditInsert/auditUpdate call sites migrate"), left untouched. Same precedent as Plan 01 D-02-ADJUNCT (profile.ts TournamentTeam) and Plan 04 (lobbySettings.ts password-change block). These sites remain candidates for a micro-refactor in a later phase if the inline-audit pattern is consolidated.

### D-05-03: D-16 tagged-enum narrowing applied to all changes objects
Tagged-enum field casts (`{ tag: 'X', value: {} } as any`) stay at per-field scope inside the `changes` object passed to `updateWithAudit` / the row literal passed to `insertWithAudit`. This is the standard narrowing pattern across all migrated sites with tagged-union fields:
- tournamentAdmin: Disqualified, Validated, TournamentHost, User, Blue, Red, Completed, Draw
- tournamentRegistration: Registered, Withdrawn
- tournamentManagement: format, stage (Draft/Cancelled), defaultGameMode, rosterVisibility, disconnectPolicy, groupAssignmentMode (Auto), Active
- seriesManagement: stage (Drafting/Shelved/BetweenGames)
- tournamentCheckIn: CheckedIn

These casts are out-of-scope for Phase 15.3 per CONTEXT.md D-03b (tagged-enum SDK friction tracked as a future follow-up phase).

### D-05-04: Plan-stated counts were aspirational
Plan frontmatter said 41 sites; actual invocation count across 8 files is 31. Same precedent as Plans 02-04. Invariants satisfied:
- Legacy calls (`auditInsert|auditUpdate`): 0 per file, verified via grep
- New-helper calls (`insertWithAudit|updateWithAudit`): 10/8/6/5/5/5/2/2 per file (includes import lines: tournamentAdmin has 1 import + 9 calls = 10; tournamentRegistration 1 import + 7 calls = 8; etc.)
