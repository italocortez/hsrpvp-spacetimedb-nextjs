<objective>
Wave 3. Decide the fate of `auditInsert` in `auditColumns.ts` based on actual post-migration conditional-site count.

**CONTEXT.md D-06 originally assumed 3 conditional sites would keep `auditInsert` callable.** RESEARCH.md surfaced that costSetManagement.ts has 5-6 MORE conditional/split-conditional sites than assumed, bringing the total to ~7 sites. Wave 3 cannot cleanly delete `auditInsert` without either splitting all 7 conditionals (Option β, high churn) or keeping the export (Option α, zero-churn).

**Decision procedure:**

1. **Verify actual conditional count post-Wave 2** via grep:
   ```bash
   grep -rn "auditInsert" spacetimedb/src --include="*.ts" | grep -v "auditColumns.ts" | grep -v "auditHelpers.ts"
   ```
   Expected output: 0 remaining non-conditional callers + N conditional callers where `auditInsert` is called inside an `existing ? ... : auditInsert(...)` ternary OR inside the `else` branch of a split if/else block.

2. **If count > 3 (likely):** Execute **Option α** — keep `auditInsert` exported, mark it as primitive-use-only with a doc comment. Wave 3 is a no-op on the export itself; add the comment + document the scope shrink in SUMMARY.

3. **If count = 0:** Execute **Option β** — delete `auditInsert` from auditColumns.ts. Run post-delete verification.

4. **If count = 1-3:** Split decision. Planner's discretion during execution — the human-adjacent pattern is Option α (consistent with Wave 0 two-tier API). Agent should default to Option α and flag the decision in SUMMARY for reviewer visibility.

Purpose: Close the scope-shrink decision cleanly per D-10 without re-litigating D-06 mid-execution.

**Note on `depends_on`:** The frontmatter `depends_on: ["15.3-07", "15.3-11"]` is illustrative — Plan 13 logically depends on every `auditInsert`-touching plan in Waves 1-2 (not just Plans 07 and 11). Wave ordering (wave:3 runs after all wave:1 + wave:2 plans complete) handles the actual dependency correctly. The two explicitly listed plans are the most salient consumers of the Option α/β decision: Plan 07 (Cluster G — reducers/* batch including heavy `auditInsert` use) and Plan 11 (costSetManagement.ts — source of the 5-6 conditional sites that drive the Option α recommendation).

Output: auditColumns.ts either unchanged with doc comment (Option α) OR with auditInsert removed (Option β); all tests still green; Option choice documented.
