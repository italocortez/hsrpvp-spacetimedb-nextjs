## Decisions Made

### D-01-ADJUNCT: Composite-PK same-shape delete+re-insert uses updateWithAudit
`calendarInviteResponse.ts` L39-45 and `calendarSaved.ts` L80-85 both do `.delete(existing)` followed by `.insert({...existing, changes, ...auditUpdate})`. Unlike admin.ts P4 (where the caller builds a completely explicit new-shape row), these sites spread `...existing` and are semantically a partial update. Migrating to `updateWithAudit(ctx, existing, {changes}, userId)` produces identical output. Kept the surrounding `.delete(existing)` call because the composite PK has no `.pk.update()` accessor. **Zero behavior change verified via calendar integration tests.**

### D-02-ADJUNCT: profile.ts TournamentTeam update NOT migrated
`profile.ts` L74-79 updates `TournamentTeam` with inline manual `lastModifiedById`/`lastModifiedDate` writes — it doesn't call `auditUpdate`. Per plan "only 3 explicit auditUpdate call sites", left untouched. Its trailing `as any` stays. The site is a candidate for a later micro-refactor if/when profile.ts is revisited.

### D-03-ADJUNCT: null → undefined for optional table columns (latent bug fix)
Old code wrote `null` for optional columns `CalendarEvent.description`, `CalendarEventInvite.respondedAt`. The outer `as any` suppressed the type error. Post-migration to `insertWithAudit<T>`, the helper's generic `T` preserves the row-literal type and `null` no longer matches `Timestamp | undefined`. Per SpacetimeDB skill rules, `undefined` is the correct representation for optional table columns (serializes to `none` — same as `null`). Switched 4 sites. **Zero persisted-data change.**
