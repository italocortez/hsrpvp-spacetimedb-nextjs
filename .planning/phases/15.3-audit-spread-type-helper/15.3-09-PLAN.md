<objective>
Wave 2 File 2. Migrate 13 audit call sites in `reducers/server.ts` — the bootstrap path. BOOTSTRAP CRITICALITY: if broken, first-DB-init fails and every downstream integration test fails with "SYSTEM user not found" or similar.

**Critical NO-TOUCH region:** L293-322 (server_set_datetime test utility) contains 3 blocks that manually write `lastModifiedById: SYSTEM_USER_ID, lastModifiedDate: ctx.timestamp` PAIRED WITH a CUSTOM timestamp on `createdDate: ts` or `lastSeenAt: ts`. These are test-utility reducers (`server_set_datetime`) that override timestamps intentionally. They CANNOT go through `updateWithAudit` because the helper forces `ctx.timestamp` — losing the custom override. See Pitfall 6 + PATTERNS.md C1 counter-example.

**Post-migration: fresh-DB smoke test REQUIRED** per RESEARCH.md §Wave 2 File 2 recipe. This is a human-verify checkpoint because SYSTEM user creation only runs on first publish — can't be exercised by a running test suite without a DB reset.

Output: File on two-tier API, L293-322 preserved verbatim, fresh-DB smoke test confirms SYSTEM user correctly stamped.
</objective>
