## Decisions Made

See key-decisions in frontmatter. Highlights:

- **D-14-01 — Strategy A for rating-admin.test.ts L337.** The placeholder sat at the tail of an `if/else` block whose else branch existed only because the original author wanted *some* assertion in every code path. Inspecting the structure showed the else branch was the last statement before the closing brace of `if (rows.length > 0)`; removing it has zero impact on control flow because there's no loop, no continue, and no subsequent statement that the else would fall through to. Strategy A leaves the code shorter and keeps the deferred-coverage rationale documented inline as a regular comment. Strategy B (commented no-op `}` else block) would have added noise without adding clarity.
- **D-14-04 — auth-security.test.ts duplicate-comment consolidation.** The original site had two adjacent comment blocks (one above the `it()`, one inside the `it()` body) that said the same thing. After the conversion to `it.todo`, the inside-body comment had nowhere to live, so I merged its substantive content ("See Task 4 how-to-verify step 4") into the surviving describe-level comment as the closing line. No information lost; one fewer comment block to skim past.
