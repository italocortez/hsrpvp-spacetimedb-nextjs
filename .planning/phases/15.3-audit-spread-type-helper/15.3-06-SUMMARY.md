### D-06-04: setEliminatedStatus L126 uses insertWithAudit (not auditUpdate semantics)
The original code at L141-145 used `...auditInsert(ctx, userId)` on a TournamentEnrolled composite-PK re-insert. This is structurally SAME-SHAPE (identical fields + status override + ...enrolled spread) but semantically uses insertWithAudit (resets createdBy/Date) rather than auditUpdate (preserves). Preserved original semantics via `insertWithAudit(ctx, {...enrolled, status}, userId)` per zero-behavior-change mandate. Whether resetting createdBy/Date on TournamentEnrolled status changes is intentional or a latent bug is outside Phase 15.3 scope. Logged as observation for future review.

### D-06-05: Dynamic-key handling in matchResultSubmission captain-confirm
`[sideFlag]: true` where `sideFlag` is a computed string (`'blueConfirmed' | 'redConfirmed'`) cannot be narrowed by TypeScript through `Partial<T>`. Applied `{ [sideFlag]: true } as any` (cast on changes object only). Narrower than the pre-existing outer-closure `} as any)` cast which absorbed the dynamic key AND the auditUpdate spread. Net: 1 `as any` on inner object vs 1 `as any` on outer closure — same count, narrower scope.
