**CREATE refereeManagement.ts with 2 reducers:**

**1. transfer_referee:**
- Permission: `getAuthenticatedUser(ctx)`
- Args: lobbyId (u32), targetUserId (u32)
- Find caller's LobbyMember row via `(ctx.db.LobbyMember as any).primaryKey.find({ lobbyId, userId: user.id })`
- Validate: caller has isReferee === true. Throw SenderError if not.
- Find target's LobbyMember row via `(ctx.db.LobbyMember as any).primaryKey.find({ lobbyId, userId: targetUserId })`
- Validate: target exists (is a member of the lobby)
- Remove referee from caller: delete + insert with isReferee = false, auditUpdate
- Add referee to target: delete + insert with isReferee = true, auditUpdate
- Pattern for composite PK update:
```typescript
ctx.db.LobbyMember.delete(senderMember);
ctx.db.LobbyMember.insert({
    ...senderMember,
    isReferee: false,
    ...auditUpdate(ctx, senderMember, user.id),
} as any);
```

**2. reclaim_referee:**
- Permission: `getAuthenticatedUser(ctx)`
- Args: lobbyId (u32)
- Find lobby, validate caller is lobby.hostUserId (only the host can reclaim)
- Find the current referee: iterate LobbyMember.lobby_id.filter(lobbyId) to find the one with isReferee === true
- If current referee is already the host, no-op
- Remove referee from current holder, add referee to host (same pattern as transfer_referee)

NOTE: Auto-assignment of the isReferee flag to the lobby host at lobby creation time is deferred to Phase 9 (lobby creation reducers). This plan only implements transfer and reclaim.

**CREATE matchResultSubmission.ts with 3 reducers:**

**1. confirm_match_scores:**
- Permission: `getAuthenticatedUser(ctx)`
- Args: matchResultId (u32)
- Find MatchResultRecord by id
- Validate: status is Pending (not yet fully submitted or disputed)
- Determine which team the caller is on:
  - If user.id === matchResult.player1Id -> set team1Confirmed = true
  - If user.id === matchResult.player2Id -> set team2Confirmed = true
  - Else throw SenderError "You are not a participant of this match"
- Update MatchResultRecord via id.update() with the confirmed flag

**2. submit_match_result:**
- Permission: `getAuthenticatedUser(ctx)`
- Args: matchResultId (u32), winnerId (u32)
- Find MatchResultRecord by id
- Validate: status is Pending
- Validate: team1Confirmed === true AND team2Confirmed === true. If not, throw SenderError "Both teams must confirm scores before submission"
- Validate: caller has referee authority for this match:
  - Find the lobby: ctx.db.Lobby.id.find(matchResult.lobbyId)
  - Find caller's LobbyMember: check isReferee === true
  - OR: if match is tournament match (tournamentId not undefined), check if caller is TO/assistant/moderator/admin via ensureTournamentAccess or isRoleAtLeast
  - Simplified: check isReferee first. If not referee, check isRoleAtLeast(user.role, 'Moderator') or (isTournamentMatch and ensureTournamentAccess passes). This gives flexibility.
- Validate: winnerId is either player1Id or player2Id (or 0 for draw if applicable)
- Update MatchResultRecord:
  - status = { tag: 'Submitted', value: {} }
  - winnerId = winnerId
  - refereeUserId = user.id
  - auditUpdate

NOTE: Phase 3 does NOT trigger MMR calculation or bracket advancement -- those are Phase 5 and Phase 4 features respectively. The submit_match_result reducer just records the submission. The comment "Submit triggers: match history archival, MMR calculation, bracket advancement" from CONTEXT.md describes the FUTURE complete flow. For now, just set the status to Submitted.

**3. dispute_match_result:**
- Permission: `getAuthenticatedUser(ctx)`
- Args: matchResultId (u32), reason (string)
- Find MatchResultRecord by id
- Validate: status is Submitted (can only dispute after submission)
- Validate: caller is player1Id or player2Id
- Validate: disputedByUserId is undefined (only one dispute per match)
- Validate: reason.trim().length > 0 and length <= 1000
- Update MatchResultRecord:
  - status = { tag: 'Disputed', value: {} }
  - disputedByUserId = user.id
  - disputeReason = reason.trim()
  - auditUpdate

Create `spacetimedb/src/reducers/tournamentAdmin.ts` with 6 reducers:

**1. dq_participant:**
- Permission: `ensureTournamentAccess(ctx, tournamentId)` -- TO, assistant, moderator, or admin
- Args: tournamentId (u32), userId (u32), reason (string)
- Find TournamentParticipant via `(ctx.db.TournamentParticipant as any).primaryKey.find({ tournamentId, userId })`
- Validate: participant exists and is not already Disqualified or Withdrawn
- Update status to { tag: 'Disqualified', value: {} } (delete + insert for composite PK)
- Log: `console.log(\`[TOURNAMENT] Participant #${userId} disqualified from tournament #${tournamentId}: ${reason}\`);`

**2. override_match_result:**
- Permission: `ensureTournamentAccess(ctx, tournamentId)` for tournament matches; `ensureModerator(ctx)` for non-tournament matches
- Args: matchResultId (u32), newStatusTag (string), winnerId (u32), reason (string)
- Find MatchResultRecord by id
- Validate newStatusTag is one of: Validated, Rejected
- If match has tournamentId: ensureTournamentAccess(ctx, matchResult.tournamentId)
- Else: ensureModerator(ctx) (only mods/admins can override non-tournament matches)
- Update MatchResultRecord:
  - status = { tag: newStatusTag, value: {} }
  - winnerId = winnerId (if Validated; if Rejected, set winnerId to undefined)
  - disputeReason = reason (use disputeReason field to store override reason)
  - auditUpdate
- NOTE: MMR compensation for overrides is deferred to Phase 5

**3. assign_tournament_assistant:**
- Permission: `ensureTournamentAccess(ctx, tournamentId)` -- but ONLY the organizer or admin/moderator can assign assistants
- Args: tournamentId (u32), userId (u32), canValidateResults (bool), canOverrideResults (bool), canDqParticipants (bool), canManageBracket (bool), canAssignSeeds (bool)
- Additional check: caller must be tournament.organizerId OR isRoleAtLeast(user.role, 'Moderator')
  (Existing assistants cannot assign other assistants)
- Validate: target user exists (ctx.db.User.id.find(userId))
- Check if assistant already exists: `(ctx.db.TournamentAssistant as any).primaryKey.find({ tournamentId, userId })`
  - If exists: delete + insert with updated permissions
  - If not exists: insert new row
- Apply auditInsert or auditUpdate as appropriate

**4. remove_tournament_assistant:**
- Permission: organizer or Moderator+ (same as assign)
- Args: tournamentId (u32), userId (u32)
- Find and delete the TournamentAssistant row
- If not found, throw SenderError

**5. mod_promote_to_host:**
- Permission: `ensureModerator(ctx)` -- only moderators and admins
- Args: userId (u32)
- Find target user
- Validate: target user's current role is User (can only promote from User to TournamentHost)
- Validate: caller cannot promote someone who is already TournamentHost or higher
- Actually per CONTEXT.md: "Moderator can promote/demote TournamentHost only (not other mods or admins)"

  - Do NOT allow promoting to Moderator (only Admin can do that, via existing admin_update_user)
- Update user role to { tag: 'TournamentHost', value: {} }
- Use ctx.db.User.id.update({ ...user, role: { tag: 'TournamentHost', value: {} }, ...auditUpdate })

**6. mod_demote_from_host:**
- Permission: `ensureModerator(ctx)` -- only moderators and admins
- Args: userId (u32)
- Find target user
- Validate: target user's current role is TournamentHost (can only demote TournamentHost to User)
- Per CONTEXT.md: "Moderator can promote/demote TournamentHost only"
- Update user role to { tag: 'User', value: {} }
- Use ctx.db.User.id.update({ ...user, role: { tag: 'User', value: {} }, ...auditUpdate })
