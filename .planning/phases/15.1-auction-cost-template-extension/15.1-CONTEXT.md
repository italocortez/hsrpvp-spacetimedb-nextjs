# Phase 15.1: Auction Cost Template Extension - Context

**Gathered:** 2026-04-14
**Status:** Ready for planning

<domain>
## Phase Boundary

Close Phase 15 IN-10 (`15-REVIEW.md:206`): extend the canonical character and lightcone templates (and the two seed pipelines that consume them) so auction cost data is ingested from the template JSON instead of being silently duplicated from classic values. Surgical scope — schema shape stays unchanged from Phase 15; pairing template/schema stays unchanged; synergy auction support is explicitly deferred to a future restructure phase.

Deliverables:
1. `test/data-templates/characters_template.json` + `lightcones_template.json` extended to the parallel sibling shape (`cost.<mode>.classic` + `cost.<mode>.auction`).
2. `test/data/characters_table.json` (83) + `lightcones_table.json` (156) re-migrated to the new shape with classic values only (auction sub-block omitted — falls to zeros on seed insert).
3. `scripts/seed-data.ts` + `test/shared/seed-data.ts` rewritten to read the new shape, with explicit zero-padding on inserts where a sub-block is absent.
4. `test/data-templates/README.md` transform tables rewritten for char/lc; pairing section untouched.
5. Partial-ingestion regression tests for char/lc (classic-only, auction-only, zero-padding on insert, preservation on update).

<decisions>
## Implementation Decisions

### Template JSON shape (char + lc only)

- **D-01:** Parallel sibling blocks per game mode. Each mode's block becomes `{ classic: { E0-E6 | S1-S5 }, auction: { E0-E6 | S1-S5 } }`. Both sub-blocks are optional at the template layer — organizers may provide one, the other, or both per mode. The old flat shape (`cost.<mode>.E0` directly) is invalidated.
- **D-02:** Pairing template (`pairing_template.json`) shape is **unchanged**. Synergy auction support is not introduced in this phase — it rides the 15.4 restructure instead.

### Scope boundaries

- **D-03:** No schema changes. `HsrCharacterCost.classicCosts`, `HsrCharacterCost.auctionBaseBid`, `HsrLightconeCost.classicCosts`, `HsrLightconeCost.auctionBaseBid` remain required `EidolonCost` / `SuperimpositionCost` struct columns. No optional fields, no new columns.
- **D-04:** No reducer signature changes. `admin_bulk_upsert`, `edit_draft_character_cost`, `edit_draft_lightcone_cost`, `edit_draft_synergy_cost` signatures are untouched. No module-binding breakage.
- **D-05:** Synergy tables (`HsrSynergyCost`, `CostSetDraftSynergy`) are **not** touched. No new `auctionCostModifier` column. Classic-only synergy cost remains the only synergy data until Phase 15.4.

### Upsert ingestion rule (unified for seed + admin_bulk_upsert)

- **D-06:** **"If the data isn't in the JSON, don't upsert it."** Pure partial-update. A field absent from the payload produces no DB change on an existing row — the current value is preserved. Matches Phase 15 D-08 partial-update semantics exactly.
- **D-07:** **Insert-case required-column padding.** When inserting a new row (no existing row found by PK tuple), required struct columns missing from the payload are zero-filled so the insert is valid:
    - `HsrCharacterCost`: missing `classicCosts` → `{e0:0, e1:0, e2:0, e3:0, e4:0, e5:0, e6:0}`; missing `auctionBaseBid` → same shape of zeros.
    - `HsrLightconeCost`: missing `classicCosts` → `{s1:0, s2:0, s3:0, s4:0, s5:0}`; missing `auctionBaseBid` → same.
    - Zero-padding is seed/insert-only. Never happens on update.
- **D-08:** **No classic → auction silent copy.** The Phase 15 placeholder `auctionBaseBid: { ...classicCosts }` in `scripts/seed-data.ts:188,237` and `test/shared/seed-data.ts:152,196` is removed. If the template provides only `classic`, the row's `auctionBaseBid` is zero-padded on insert — not a copy of classic.

### Seed fan-out

- **D-09:** For each `cost.<mode>` block present in the template:
    1. If `classic` sub-block is present → that mode's DB row gets `classicCosts: { e0..e6 }` (or `s1..s5`) from the values.
    2. If `auction` sub-block is present → that row gets `auctionBaseBid: { e0..e6 }` (or `s1..s5`).
    3. Sub-block absent but the other is present → zero-pad the missing side (D-07).
    4. Both absent → no row written for that mode (skip entirely).
- **D-10:** For each `cost.<mode>` block **absent** from the template entry: no `HsrCharacterCost` / `HsrLightconeCost` row written for that mode. Absence of mode = not configured.

### Data file migration

- **D-11:** `test/data/characters_table.json` (83 entries): each entry's `cost.<mode>` block restructured from flat `{E0-E6}` to `{ classic: { E0-E6 } }`. No `auction` sub-block emitted — defaults to zeros on seed insert. Preserves existing classic values exactly.
- **D-12:** `test/data/lightcones_table.json` (156 entries): same treatment — `{S1-S5}` → `{ classic: { S1-S5 } }`, no `auction` sub-block.
- **D-13:** `test/data/pairing_table.json` (10 entries): **unchanged**. Pairing shape is not part of 15.1.
- **D-14:** `_old` backup files from Phase 15 may be deleted in a cleanup commit once phase is green (Claude's discretion — matches Phase 15 D-28 pattern).

### Reducer reader safety

- **D-15:** No changes needed. Existing readers already tolerate zero values:
    - `draftClassic.ts:367-368` uses `cost = costRow.classicCosts[eidolonKey] ?? 0` and `if (!costRow) return 0`.
    - `draftAuction.ts:60-61` uses `return costRow.auctionBaseBid[eidolonKey] ?? 0`.
    - `postDraft.ts:55` has `if (costRow && costRow.classicCosts)` guard.
  When auction values are all zeros for the default seed, `draftAuction.getCharacterBaseCost` legitimately returns 0 — the intended behavior for the pre-tuning default set.

### Router validation

- **D-16:** No validation tightening in `admin_bulk_upsert`. Existing `EidolonCost` / `SuperimpositionCost` struct schema + `validateEnum` + `validateKeys` are sufficient. Adding defensive checks creates friction without preventing real data corruption.

### README rewrite

- **D-17:** `test/data-templates/README.md` transform tables for characters and lightcones rewritten to reflect the `{ classic, auction }` sub-block shape. The L84 note *"auctionBaseBid uses the same values as classicCosts for now (placeholder; the auction format may diverge in a later phase)"* is removed — the auction format has diverged. Pairing section kept as-is.

### Tests

- **D-18:** Add regression tests for the partial-ingestion path:
    1. **Classic-only template entry (seed path):** insert a character whose template JSON has only `cost.memory_of_chaos.classic`; assert the resulting `HsrCharacterCost` row has classic populated and `auctionBaseBid` = all zeros.
    2. **Auction-only template entry (seed path):** mirror of the above with only `cost.memory_of_chaos.auction`; assert `classicCosts` is zero-padded.
    3. **Absent mode block:** confirm no `HsrCharacterCost` row exists for that (character, mode, costSetId) tuple.
    4. **Update preservation:** pre-insert a row with both fields populated; then issue a partial upsert with only `classicCosts`; assert `auctionBaseBid` is untouched (no zeroing on update).
    5. **Default seed regression:** post-seed against the fully-migrated `characters_table.json` + `lightcones_table.json`, assert every character has 3 rows (one per game mode), each with real classic values and zero auction values.
- **D-19:** Existing tests (`test/backend/cost-sets/cost-set-lifecycle.test.ts`, `test/backend/reducers/admin/cost-set-pk.test.ts`) continue to pass unchanged — they always send both JSON arguments fully populated.

### Claude's Discretion

- JSON-null semantics in `admin_bulk_upsert` — whether an explicit `null` in the payload means "clear to zeros" vs "treat as absent" (planner decides and documents; current code treats missing keys as absent).
- Whether to split the phase commit as (schema-free) [data + template] → [seed] → [README + tests], or ship as one logical commit after phase green.
- Cleanup of `_old` data backup files from Phase 15.
- Extraction of shared seed transforms into `test/shared/transforms.ts` (same Claude discretion call as Phase 15 D-25 — follow-up vs in-phase).

### Folded Todos

None — no pending todos matched Phase 15.1 scope (the IN-10 trigger is a REVIEW entry, not a pending todo).

<specifics>
## Specific Ideas

- User explicitly rejected auto-duplication of classic → auction during seed: *"I only expect to have classic filled and draft can be filled with 0s."* Zero-padding on insert is the right semantic — not a placeholder copy.
- User prefers surgical scope when the bigger refactor is clearly identifiable: *"be very surgical, needs code exploration."* This phase deliberately stays within template + seed; the broader cost-table `draftMode` column restructure is deferred to 15.4 (see Deferred Ideas).
- User's GA-3 clarification: default cost set must be fully populated across all game modes × both draft modes. Custom cost sets can ship partial (1 game mode × 1 draft mode minimum). In this phase's terms: default seed covers all 3 modes with classic values + zero auction; partial custom sets are exercised by the D-18 tests.
- Synergy architecture observation during discussion: neither `draftClassic.ts` nor `draftAuction.ts` currently read `HsrSynergyCost` at all — the `costModifier` column is dormant. This is why synergy auction is safely deferrable; no draft reducer is forced to care about its shape yet.

</specifics>

## Deferred Ideas

All deferred items below have been captured as todos under `.planning/todos/pending/` so they do not disappear with this phase.

- **Cost-table `draftMode` column restructure** (future Phase 15.4 candidate) — replace `classicCosts` + `auctionBaseBid` columns on `HsrCharacterCost` / `HsrLightconeCost` with a single `costs` struct + `draftMode: DraftMode` column; same pattern for synergy (add `draftMode`, keep single `costModifier`). PK tuple extended to include `draftMode`. Must land before Phase 16 / Phase 17 so the cost-tables frontend is written once against the clean shape. Architecturally correct; deferred out of 15.1 because the blast radius is a full refactor of all cost-reading code paths.
- **Synergy half-assignment cost math + lobby broadcast** (future Match-Data phase — user's term, not yet a roadmap phase) — post-draft, players assign drafted characters to match halves; same-half paired characters apply the `costModifier`. Must broadcast to all lobby members, not just the editing player. Auction variant applies the surcharge against remaining lightcone budget after the bid phase. Requires synergy math to first become a real reducer concern — 15.4 prerequisite.
- **Lobby-creation validation for cost-set coverage** — reject lobby creation when the selected cost set does not cover the lobby's (game mode × draft mode). Prevents organizers from accidentally using partial custom sets in contexts where everyone would cost zero. Blocks on 15.4 because the right coverage check depends on the restructured row shape.
- **CostSetDraft* consolidation review** — architectural evaluation of whether `CostSetDraftCharacter` / `CostSetDraftLightcone` / `CostSetDraftSynergy` tables can be removed in favor of direct editing on live tables with `isPublished=true` visibility gating. Must address (a) broadcast cost of making editing public, (b) replay integrity when costs are mutated post-publish, (c) whether match-history tables need to snapshot cost-set contents at finalization time. Not a template concern; separate investigation.
