<code_context>
## Existing Code Insights

### Reusable Assets
- **Phase 12.2 upgrade pattern:** Atomic-commit + full-test + maincloud republish + smoke-verify worked cleanly for 2.0.3→2.1.0. Replicate the same shape, scaled to 2 atomic commits instead of 1.
- **`npm run generate` (root):** Cargo-based bindings generator already wired; runs `npm --prefix spacetimedb install` first, then cargo, then prettier. Single command produces the bindings regen artifact for Commit B.
- **`npm run spacetime:publish` (root):** Maincloud publish already configured (`--server maincloud`). No CLI server reconfiguration needed.

### Established Patterns
- **Two-side dependency declaration:** `spacetimedb` package appears in BOTH `spacetimedb/package.json` (module/server side) AND root `package.json` (client side). Per the drift-narrative postscript, the unscoped `spacetimedb` package serves both roles via subpath exports (`spacetimedb/server`, `spacetimedb/react`, etc.). Both manifests must move together at v2.2.0; only the module side moves at v2.1.0 (drift fix).
- **Lockfile-strict installs in CI:** Per the drift narrative, lockfile-strict `npm ci` is likely how the 2.0.3 entry persisted. Use plain `npm install` for the bump commits to force re-resolution.
- **Bindings checked in:** `src/module_bindings/` is committed (not gitignored). Regen happens at SDK-bump time and lands in the same commit as the bump.
- **Publish + bootstrap two-step:** `spacetime publish --clear-database` followed immediately by `scripts/post-publish.ts` is the canonical reset flow. 16.3 republish does NOT use `--clear-database` (we're republishing the same schema, not resetting), so post-publish.ts is not invoked in this phase.

### Integration Points
- **Module bindings ↔ frontend:** All typed table/view/reducer accessors flow from `src/module_bindings/` into `components/`, `hooks/`, `app/`. A non-cosmetic codegen change would surface as typecheck failures across many call sites — the test suite is the structural sensor.
- **`spacetimedb/server` subpath exports:** Reducer authoring imports come from `"spacetimedb"` in `spacetimedb/src/**`. v2.2.0 adds `AuthCtx` / `JwtClaims` exports to the server subpath — visible to typecheck after bump but NOT consumed in this phase (16.4 owns adoption).
- **`spacetimedb/react` subpath exports:** Client-side React hooks (`useTable`, `useReducer`, etc.) come from this subpath. v2.2.0 adds `useTable({ enabled })` and `useProcedure` — typed surfaces become available after bump but NOT consumed here (16.4 owns adoption).

</code_context>
