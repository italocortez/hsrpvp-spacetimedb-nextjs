## Accomplishments

- Eliminated all TournamentParticipant and teamGroupId usage from 8 source files (0 remaining occurrences)
- Implemented `transferTournamentCaptain` deterministic helper (lowest userId wins) used across registration, teams, and admin DQ
- DQ reducer now handles 3 lobby scenarios: active draft (kick+force-concede), shelved/BetweenGames (hard-delete), no lobby (bracket auto-advance)
- `override_match_result` migrated to `winnerTeamSide`+`matchEndReason` and derives tournamentId via bracketMatch (D-42)

## Decisions Made

- `register_for_tournament` no longer accepts `teamGroupId` parameter — enrollment and team assignment are now fully decoupled. Clients registering for team tournaments must call `create_tournament_team` / `request_join_team` after registering.
- `override_match_result` reducer signature changed: `winnerId: u32` replaced with `winnerTeamSideTag: string` ('Blue', 'Red', or '' for draw). This is a breaking change for any existing client calls.
- `transferTournamentCaptain` returns `boolean` — callers must handle `false` (no members left) by destroying the team themselves. This keeps the helper single-responsibility.
- DQ during Shelved/BetweenGames uses `hardDeleteLobby` (not `performConcede`) — shelved lobbies have no active match state to concede from.
