## Game Transition Model

### How should the lobby transition between games in a best-of-N series?

| Option | Description | Selected |
|--------|-------------|----------|
| Reset-in-place + shelve | Same MatchSession row. BetweenGames + Shelved stages. | partially |
| Snapshot + recreate | Snapshot series state, close lobby, recreate to continue. | |
| Separate lobby per game | Each game gets own Lobby+MatchSession. New MatchSeries table. | |

**User's input:** Reset-in-place, but need shelving across sessions. Budgets reset every game — only carry gamesWon and currentGameNumber.

### When does lobby enter Shelved state?

| Option | Description | Selected |
|--------|-------------|----------|
| Auto-shelve after every game | Always transitions to Shelved after scoring. | |
| Player-initiated shelve | Choice in BetweenGames: continue, shelve, or concede. | ✓ |

**User's input:** Player-initiated. 3rd party referee has authority via `refereeControlsShelving` (default true).

### Can a series be shelved mid-game?

| Option | Description | Selected |
|--------|-------------|----------|
| Between games only | Shelving only in BetweenGames stage. | ✓ |
| Mid-game shelving too | Allow during Drafting/Equipping/Scoring. | |

### Shelved lobby expiry?

| Option | Description | Selected |
|--------|-------------|----------|
| Configurable TTL | 72h casual, tournament persists until cancel. | ✓ |
| Persist indefinitely | No auto-expiry. | |
| Tournament vs casual split | Tournament indefinite, casual 24h. | |

**User's input:** Tournament persists until cancel (cascade delete). Non-tournament voided after 72h via existing hard-delete GC mechanism.

### Unshelve requirements?

**User's input:** At least 1 player per team (not all). Referee not required. Can play short-handed. Unshelve authority: host, TO, TO assistant, admin, mod only.

### BetweenGames actions?

**User's input:** Continue now, shelve, or concede. Concede surrenders the entire series.

## Team Split: Orphan Handling

### When captain withdraws and team disbands, what happens to orphaned members?

| Option | Description | Selected |
|--------|-------------|----------|
| Stay enrolled, teamless | TTM rows deleted, TournamentEnrolled stays. Can join another team. | ✓ |
| Auto-create solo teams | Each orphan gets auto-team. | |
| Auto-withdraw orphans | Status → Withdrawn, must re-register. | |

### DQ cascade for TournamentTeamMember?

**Initial options presented:** Delete TTM on DQ vs Keep TTM and filter by status.

**User correction:** DQ can happen at any point (not just pre-tournament). What about active lobbies, shelved series?

**User correction #2:** Captain DQ shouldn't disband team — just transfer captain flag to next member. Team survives.

**Final decision:** Captain DQ → captain-transfer, team survives. Captain withdrawal → also captain-transfer. Only destroy team when last member removed.

### TournamentTeamMember schema?

| Option | Description | Selected |
|--------|-------------|----------|
| Include tournamentId | PK: [teamId, userId], plus tournamentId column + index. | ✓ |
| Derive from TournamentTeam | PK only, two-step lookup. | |

### Bracket impact of DQ?

**User's question:** What happens to brackets when player is DQ'd?

**Answer:** Team survives = no bracket change. Team destroyed (last member) = auto-advance opponent. Past results stand. Current active match resolved. Future rounds unaffected (teams placed on advance).
