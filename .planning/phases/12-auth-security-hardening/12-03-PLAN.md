**A. Add identity verification function to the API route (D-09, D-10):**

Rewrite `app/api/auth/link-discord/route.ts` to:
1. Accept `spacetimeToken` instead of `callerIdentityHex` in the request body
2. Create an ephemeral SpacetimeDB connection with the client's token to extract the server-verified identity
3. Use the existing server connection singleton for the actual reducer call (D-10)

The full rewritten route:

```typescript
import { getServerSession } from 'next-auth';
import { NextResponse } from 'next/server';
import { getServerConnection } from '@/lib/spacetimedb-server';
import { authOptions } from '@/app/api/auth/authOptions';
import { DbConnection } from '@/src/module_bindings';

// Environment — same as lib/spacetimedb-server.ts
let HOST = process.env.SPACETIMEDB_HOST ?? 'wss://maincloud.spacetimedb.com';
if (HOST.startsWith('https://')) HOST = HOST.replace('https://', 'wss://');
else if (HOST.startsWith('http://')) HOST = HOST.replace('http://', 'ws://');
const DB_NAME = process.env.SPACETIMEDB_DB_NAME ?? 'nextjs-ts';

/**
 * Verify a SpacetimeDB auth token by creating an ephemeral connection.
 * Returns the hex string of the verified identity.
 * Timeout after 5 seconds.
 */
async function verifySpacetimeIdentity(spacetimeToken: string): Promise<string> {
    return new Promise<string>((resolve, reject) => {
        const timeout = setTimeout(() => {
            reject(new Error('Identity verification timeout'));
        }, 5000);

        DbConnection.builder()
            .withUri(HOST)
            .withDatabaseName(DB_NAME)
            .withToken(spacetimeToken)
            .onConnect((conn, identity) => {
                clearTimeout(timeout);
                conn.disconnect();
                resolve(identity.toHexString());
            })
            .onConnectError((_ctx, err) => {
                clearTimeout(timeout);
                reject(new Error(`Invalid SpacetimeDB token: ${err}`));
            })
            .onDisconnect(() => {})
            .build();
    });
}

/**
 * POST /api/auth/link-discord
 *
 * Called by the client after Discord OAuth completes.
 * Verifies the NextAuth session server-side (trusted), verifies the SpacetimeDB
 * identity via ephemeral connection (D-09), then calls server_link_provider
 * on SpacetimeDB with the verified identity and Discord info.
 *
 * Body: { spacetimeToken: string }
 */
export async function POST(request: Request) {
    // 1. Verify the Discord session server-side
    const session = await getServerSession(authOptions);
    if (!session?.user) {
        return NextResponse.json({ error: 'Not authenticated with Discord' }, { status: 401 });
    }

    const discordUser = session.user as any;
    const discordId = discordUser.id;
    const discordUsername = discordUser.name || 'DiscordUser';

    if (!discordId) {
        return NextResponse.json({ error: 'Discord ID not found in session' }, { status: 400 });
    }

    // 2. Parse the client's SpacetimeDB token from the request body
    let body: any;
    try {
        body = await request.json();
    } catch {
        return NextResponse.json({ error: 'Invalid JSON body' }, { status: 400 });
    }

    const { spacetimeToken } = body;
    if (!spacetimeToken || typeof spacetimeToken !== 'string') {
        return NextResponse.json({ error: 'spacetimeToken is required' }, { status: 400 });
    }

    // 3. Verify the SpacetimeDB identity via ephemeral connection (D-09)
    let callerIdentityHex: string;
    try {
        callerIdentityHex = await verifySpacetimeIdentity(spacetimeToken);
    } catch (err: any) {
        console.error('[link-discord] Identity verification failed:', err.message);
        return NextResponse.json(
            { error: 'Failed to verify SpacetimeDB identity' },
            { status: 401 }
        );
    }

    // 4. Call server_link_provider via the trusted server connection (D-10)
    try {
        const conn = await getServerConnection();
        conn.reducers.serverLinkProvider({
            callerIdentityHex,
            provider: 'discord',
            providerId: discordId,
            providerName: discordUsername,
        });

        return NextResponse.json({ ok: true });
    } catch (err: any) {
        console.error('[link-discord] Failed:', err);
        return NextResponse.json(
            { error: err.message || 'Failed to link Discord account' },
            { status: 500 }
        );
    }
}
```

Key changes:
- Body accepts `spacetimeToken` instead of `callerIdentityHex`
- `verifySpacetimeIdentity()` creates ephemeral connection with client's token, extracts identity hex server-side
- Reducer call changed from `serverLinkDiscord` to `serverLinkProvider` with new params (provider: 'discord', providerId, providerName)
- Ephemeral connection has 5s timeout and calls `conn.disconnect()` in all paths (Pitfall 5)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client browser → API route | Client sends SpacetimeDB token; API route verifies via ephemeral connection |
| Client → UserIdentity table | Table now private; clients cannot subscribe directly; must use view_my_identity |
| useAuth.ts → link-discord route | Sends token from localStorage instead of identity hex |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-11 | S (Spoofing) | API route identity | mitigate | Replace client-supplied identity hex with server-verified identity via ephemeral DbConnection (D-09). Token is validated by SpacetimeDB server — only fires onConnect for valid tokens. |
| T-12-12 | I (Info Disclosure) | UserIdentity table | mitigate | Set public: false on UserIdentity table. All ~600 identity-to-user mappings no longer broadcast to every client. view_my_identity returns only caller's own row (D-14). |
| T-12-13 | D (Denial of Service) | Ephemeral connection | mitigate | 5-second timeout + conn.disconnect() on all paths (success, error, timeout). Prevents connection leaks (Pitfall 5). |
| T-12-14 | R (Repudiation) | Token theft | accept | SpacetimeDB token in localStorage is same risk as any session token. No additional mitigation needed — standard web auth threat. |
</threat_model>
