## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous WS client → SpacetimeDB module | Unauthenticated caller subscribes to any registered view/table; server enforces only via view body `ctx.sender` predicates and table `public:` flag |
| developer workstation → maincloud | `spacetime publish` uploads a new module schema; data preservation depends on non-destructive migration |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.5-01 | Information Disclosure | Adversarial raw `SELECT * FROM user` subscription bypassing any frontend gate — `User.public=true` means any WS client can subscribe directly, not via useAuth | accept | Inherits 15.2 D-01 (`User.public=true` stays; closing this would require `User.public=false` + on-demand read reducers, explicitly deferred in CONTEXT.md). Documented accepted tradeoff; 15.5 scope is "our frontend does not auto-subscribe anonymous," not "adversarial clients cannot query User." |
| T-15.5-02 | Spoofing (cosmetic UI only) | `guestLoginPending` spinner state manipulated via browser DevTools | accept | Not applicable to this plan (no UI in Plan 01). Listed here for parity with Plans 02-04; Plan 02 owns the client-side spinner. State has no auth significance — cannot elevate privilege. |
| T-15.5-03 | Elevation of Privilege | Stale `stdb_session` cookie used to pre-open Stage 2 after token revocation | mitigate (defense-in-depth) | Not applicable to this plan (Stage 2 gate lives in Plan 02). The SpacetimeDB WS handshake enforces token validity — if revoked, `isActive` stays false and no subscription fires regardless of client gate state. Plan 02 honors this by guarding Stage 2 effect on `isActive` before evaluating `stage2Gate`. |

**ASVS L1 applicability:** No high-severity threat introduced by Plan 01. The view retirement reduces egress surface (one fewer cosmetic view registered); the rename is a semantic no-op on the access-control layer.
