#### Pattern D: Stage 2 effect (new — modelled on Stage 1 shape)

```typescript
// New Stage 2 effect — copy Stage 1 structure, swap subscription + callbacks
const stage2Ref = useRef(false);   // <- add alongside stage1Ref near top of hook

useEffect(() => {
    if (!isActive || !stage2Gate || stage2Ref.current) return;
    const conn = getConnection();
    if (!conn) return;
    stage2Ref.current = true;          // <- synchronous, before subscriptionBuilder

    conn.subscriptionBuilder()
        .onApplied(() => {
            readProfileRef.current(conn);   // use stable ref, not readProfileFromConnection directly
        })
        .subscribe('SELECT * FROM user');

    // MOVED from Stage 1 — must register after SELECT * FROM user subscription
    const onUserInsert = (ctx: any, row: any) => {
        if (!isLiveChange(ctx)) return;
        console.log(`[useAuth] User.onInsert: id=${row?.id} username=${row?.username}`);
        readProfileRef.current(conn);
    };
    const onUserUpdate = (ctx: any, oldRow: any, row: any) => {
        if (!isLiveChange(ctx)) return;
        console.log(`[useAuth] User.onUpdate: id=${row?.id} username=${row?.username} (was: ${oldRow?.username})`);
        readProfileRef.current(conn);
    };
    conn.db.User.onInsert(onUserInsert);
    conn.db.User.onUpdate(onUserUpdate);

    return () => {
        conn.db.User.removeOnInsert(onUserInsert);
        conn.db.User.removeOnUpdate(onUserUpdate);
        stage2Ref.current = false;
        // NOTE: do NOT reset setProfileReady here — Stage 1 owns that flag
    };
}, [isActive, stage2Gate, getConnection]);
```

Dependency array `[isActive, stage2Gate, getConnection]` — `stage2Gate` is the derived boolean; `readProfileRef` is a ref (not in deps); `isLiveChange` is defined inline in the hook body (stable).

## Shared Patterns

### Double-Subscribe Guard (ref-based)
**Source:** `components/features/auth/hooks/useAuth.ts:17,20–24`
**Apply to:** Both Stage 1 and Stage 2 effects in the refactored `useAuth.ts`

```typescript
const stage1Ref = useRef(false);
// ... effect:
if (!isActive || stage1Ref.current) return;
// ...
stage1Ref.current = true;   // synchronous, first line inside guard
// ... cleanup:
stage1Ref.current = false;
```

The `true` assignment is the first statement after the null guards — this is the established StrictMode-safe pattern for subscription effects in this codebase. Do NOT use `useState` for this guard.

---

### SpacetimeDB `subscriptionBuilder` + `onApplied` Shape
**Source:** `components/features/auth/hooks/useAuth.ts:26–38`
**Apply to:** Both Stage 1 and Stage 2 subscription calls

```typescript
conn.subscriptionBuilder()
    .onApplied(() => {
        // Initial data is in cache — safe to read conn.db.*
    })
    .subscribe('SELECT * FROM <table_or_view>');
```

The `.onApplied()` callback fires exactly once when the server's initial response for this subscription lands. All post-subscription reads happen here, not in the effect body.

---

### Stable Ref for Callback (avoids dep-array churn)
**Source:** `components/features/auth/hooks/useAuth.ts:110,173`
**Apply to:** Stage 2 `onApplied` and `onUserInsert` / `onUserUpdate` callbacks

```typescript
const readProfileRef = useRef<(conn: any) => void>(() => {});
// ...
readProfileRef.current = readProfileFromConnection;  // updated every render
// Inside effects: readProfileRef.current(conn)   <- stable reference
```

Stage 2's `onApplied` calls `readProfileRef.current(conn)`, not `readProfileFromConnection(conn)` directly. This keeps `readProfileFromConnection` out of the Stage 2 dep array (it changes when `identity` / `session` / `setResolvedUser` change, which would retrigger Stage 2).

## Anti-Patterns Flagged (for planner to include in executor guardrails)

| Anti-pattern | Risk | Where it bites |
|---|---|---|
| `useState` for `stage1Ref` / `stage2Ref` | Re-render triggers re-subscription | Both effects — use `useRef` only |
| `conn.db.User.onInsert` left in Stage 1 | Dead callback for anon visitors; architectural mismatch | Stage 1 cleanup section |
| `stage2Ref.current = true` NOT first in effect body | StrictMode double-subscribe | Stage 2 effect guard |
| `guestLoginPending` cleared only in `.catch()` | Spinner stays after successful login | `loginGuest` + `currentUser` effect |
| Running `spacetime generate` after deletion only (before rename publish) | Intermediate stale bindings | Wave 1 sequencing |
| Manual edit of `*_table.ts` files | Overwritten on next regen | Both `module_bindings/` dirs |
| `readProfileFromConnection` in Stage 2 dep array | Retriggers Stage 2 on identity change | Stage 2 effect deps — use `readProfileRef.current` |
