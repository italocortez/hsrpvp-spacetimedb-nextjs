# Phase 12.2: SDK Upgrade Audit (2.0.3 → 2.1.0) - Context

**Gathered:** 2026-04-09 (updated)
**Status:** Ready for planning

<domain>
## Phase Boundary

Audit the SpacetimeDB SDK upgrade from 2.0.3 to 2.1.0. Export all views for proper registration, regenerate client bindings with view support, rework the frontend auth flow to use typed view data, disable confirmed reads, add error handling to touched reducer calls, and verify no regressions in existing tests or behavior.

</domain>

<decisions>
## Implementation Decisions

### View Export Migration
- **D-01:** Export all 31 views — 23 from `securityViews.ts` + 8 from `anonymousViews.ts`. One-time migration, no partial rollout.
- **D-02:** Export pattern: `export const view_xxx = spacetimedb.view(...)` (same as proven `view_my_profile` POC).
- **D-03:** Re-export all views from `index.ts` module entry point.
- **D-04:** Regenerate client bindings after export. Verify all 31 views appear in `tablesSchema` with typed accessors.
- **D-05:** Verify all views appear in `st_view` system table after publish.

### Auth Flow Rework
- **D-06:** Replace all raw SQL subscription strings with typed view bindings wherever possible. `conn.db.view_my_profile` instead of `SELECT * FROM view_my_profile`.
- **D-07:** Views are the data source for private fields (UserPrivate). Do NOT use `useTable` where view data is needed — views provide the merged User + UserPrivate data that tables can't.
- **D-08:** Keep the view-based subscription pattern for `view_my_profile` and `view_my_identity`. These are the primary data sources for auth state.
- **D-09:** Profile resolution strategy: read from typed `conn.db.view_my_profile` binding instead of `conn.db.User`. The 3-fallback resolution (localStorage cache, guest username, session name) stays but targets view data.
- **D-10:** Populate `discordId`/`discordUsername` on the frontend `User` type from `view_my_profile` view data (was always `undefined` before because view wasn't registering).

### Confirmed Reads
- **D-11:** Disable confirmed reads. Add `.withConfirmedReads(false)` to the connection builder in `app/providers.tsx`. Revert to pre-2.1.0 behavior to avoid latency increase.

### Error Handling
- **D-12:** Add `_then()` error callbacks to all frontend reducer call sites touched during the auth refactor. Not a full codebase audit — scoped to files already being modified.
- **D-13:** `_then()` pattern: log failure, surface error to user where appropriate. No retry logic unless the specific reducer warrants it.

### Reducer & Test Audit
- **D-14:** Run full backend test suite against SDK 2.1.0. Fix any failures.
- **D-15:** Proactively audit reducers for patterns that relied on 2.0.3-specific behavior (subscription semantics, isReady timing, event delivery order). Not just "fix what breaks" — actively look for 2.0.3 assumptions.
- **D-16:** Review v2.0.4/v2.0.5/v2.1.0 changelogs for breaking changes affecting our patterns. Cross-reference identified changes against codebase usage.

### Subscription Cleanup
- **D-17:** Remove dead `view_my_identity` SQL subscription if now accessible via typed binding after export.
- **D-18:** Audit all remaining SQL string subscriptions across the frontend. Replace with typed view bindings where a matching exported view exists.

### Claude's Discretion
- Internal helper organization during view export (batch vs individual exports)
- Exact error messages in `_then()` callbacks
- Order of view re-exports in `index.ts`
- Whether to group anonymous views separately in re-exports or mix with security views

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **view_my_profile POC pattern:** Proven export pattern in `securityViews.ts` line 217 — replicate for all 31 views
- **tablesSchema generation:** `spacetime generate` already handles views alongside tables — no custom codegen needed
- **AuthProvider context:** Existing provider tree in `app/providers.tsx` wraps SpacetimeDB connection — single place for `.withConfirmedReads(false)`

### Established Patterns
- **View definition:** `spacetimedb.view()` for authenticated views, `spacetimedb.anonymousView()` for public views
- **Subscription:** Currently raw SQL strings (`SELECT * FROM view_xxx`) — migrating to typed bindings
- **Profile resolution:** 3-strategy fallback (localStorage PK, guest username, session name) — keep but retarget to view data
- **Table callbacks:** `User.onInsert/onUpdate` with tag filtering (`Reducer` or `Transaction`) — may need to target view table after migration

### Integration Points
- **useAuth.ts ↔ view_my_profile:** Primary auth state source. Subscription must fire `onApplied` for `setProfileReady(true)`
- **useAuth.ts ↔ view_my_identity:** Identity mapping. Currently dead (not exported). Will work after export migration.
- **providers.tsx ↔ DbConnection.builder():** Connection config including confirmed reads setting
- **module_bindings/ ↔ frontend:** All typed view accessors flow from `spacetime generate` output

</code_context>
