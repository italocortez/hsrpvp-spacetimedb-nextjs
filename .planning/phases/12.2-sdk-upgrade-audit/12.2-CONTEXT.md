<decisions>
## Exploration Findings (2026-04-09)

### Root Cause: Views Not Registering

**Discovery:** SpacetimeDB views defined with `spacetimedb.view()` must be **exported** from the module entry point (like reducers) for the `[registerExport]` symbol to fire during module initialization. Side-effect imports (`import './views/securityViews'`) execute the code but the returned view function is discarded — the runtime never finds it in the module exports, so `registerView()` never completes.

**Evidence:**
- `st_view` was empty after publish with side-effect imports
- After changing to `export const view_my_profile = spacetimedb.view(...)` + re-export from `index.ts`, `st_view` showed the view registered
- `spacetime generate` then produced `view_my_profile_table.ts` with typed bindings
- Client-side `conn.db.view_my_profile` became accessible with `.count()`, `.iter()`, and full row data

### SDK Version Mismatch

- CLI was at v2.1.0, npm package was at v2.0.3
- Upgraded npm to 2.1.0 to match
- The view codegen existed in both versions (committed Oct 2024), but the export fix was the real blocker

### View Binding Behavior (Verified)

- Views are generated into `tablesSchema` alongside tables (same `__table()` call)
- Views have empty indexes and constraints (read-only)
- Accessor name is snake_case: `conn.db.view_my_profile` (not PascalCase like tables)
- View data is reactive — updates when underlying tables change
- `onApplied` fires once per subscription, view data available via `.iter()` after that

### Current Frontend Auth Flow Issues

1. **`view_my_profile` subscription works** but was previously dead (no bindings → SDK crashed silently)
2. **`discordId`/`discordUsername` on frontend `User` type** are always `undefined` — they exist only on UserPrivate, merged into the view. Now accessible via `conn.db.view_my_profile`
3. **`view_my_identity` subscription** is also dead (same export issue) — needs export + re-export
4. **No error handling** on `loginAsGuest` or `deleteGuestAccount` reducer calls — `_then()` pattern should be added
5. **`setProfileReady(true)` currently works** via the failure path in `readProfileFromConnection`, not via the view's `onApplied` (which never fired before the fix)

### What view_my_profile Returns

`MyProfileRow` struct with merged User + UserPrivate fields:
- All User fields: id, username, displayName, isGuest, isOnline, isPrivate, lastLoginAt, role, hasDiscordLinked, avatarCharacterName, displayedAchievementId, deletedAt
- UserPrivate fields: discordId (optional), discordUsername (optional), email (optional)
- Audit columns: createdById, createdDate, lastModifiedById, lastModifiedDate

### Proof-of-Concept Commit

`20ffbd3` — exports `view_my_profile` only. Verified:
- `st_view` shows 1 registered view
- `view_my_profile_table.ts` generated with correct schema
- `conn.db.view_my_profile.count()` returns `1n` after login
- Full row data accessible via `.iter()`

## Implementation Scope

### Must Do
1. Export all 24 views from `securityViews.ts` (assign to `export const`)
2. Export all views from `anonymousViews.ts` (same pattern)
3. Re-export all views from `index.ts`
4. Regenerate client bindings — verify all views produce typed accessors
5. Run full backend test suite — fix any 2.1.0 regressions
6. Update `useAuth.ts` to read profile from `conn.db.view_my_profile` instead of `conn.db.User`
7. Populate `discordId`/`discordUsername` from view data on the frontend `User` type
8. Add `_then()` error handling to `loginAsGuest` and `deleteGuestAccount`

### Should Do
9. Audit all SQL string subscriptions — replace with typed query builder where possible
10. Review confirmed reads default change (v2.1.0 enables by default)
11. Review v2.0.4/v2.0.5/v2.1.0 changelogs for other breaking changes
12. Clean up dead `view_my_identity` SQL subscription or export that view too

### Could Defer
13. Replace manual `conn.db.User.onInsert/onUpdate` with `useTable` callbacks
14. Replace `conn.reducers.loginAsGuest({})` with `useReducer` hook pattern
