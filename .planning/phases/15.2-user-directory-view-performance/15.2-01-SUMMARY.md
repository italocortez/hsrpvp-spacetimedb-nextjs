## Decisions Made

- **deletedAt: undefined retained in both insert payloads** — D-13/D-14 said to remove `deletedAt: undefined` (treating it as dead ceremony), but the SpacetimeDB TypeScript insert type requires all `option()` columns to be present as keys (even with value `undefined`). Omitting the key causes a TSC error. The substantive dead code was `isPrivate: false` (which was removed). `deletedAt: undefined` stays until Plan 04's binding regen updates the insert type to reflect the column being optional-by-default.

- **Module bindings manually synced** — The three binding files under `spacetimedb/src/module_bindings/` still declared `isPrivate`, causing TSC errors in `auth.ts` and `server.ts` inserts. Manually removed `isPrivate` from the generated files to unblock TSC. Plan 04's `spacetime generate` will produce the definitive regen.

## Issues Encountered

TSC initially failed after removing `deletedAt: undefined` — the SpacetimeDB insert type treats `option()` columns as required keys (value may be `undefined`, but the key must be present in the object literal). This is a known SDK pattern; the plan's CONTEXT.md note that "optional column, default undefined already" is correct at runtime but not at compile time with strict TypeScript.
