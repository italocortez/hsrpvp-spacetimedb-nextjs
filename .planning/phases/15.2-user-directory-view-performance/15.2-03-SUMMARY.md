## Accomplishments

- NEW `spacetimedb/src/helpers/userLabel.ts`: exports `resolveUserLabel(ctx, userId)` with three-path resolution — live User → DeletedUser archive → synthetic `User #N` fallback. Returns `{ displayName: string; isDeleted: boolean }` struct.
- `performUserDeletion` non-guest branch rewritten: `DeletedUser.insert({ id, displayName, isGuest, deletedAt })` then `User.id.delete(user.id)`. The `username: 'deleted_${id}'` in-place ghost pattern is eradicated. Guest fast-path (`isGuest && !hasHistoryReferences`) unchanged byte-for-byte.
- `hasHistoryReferences` check set is unchanged — 8 tables, no DeletedUser added (DeletedUser is the eviction destination, not a history reference table).
- `server_nuke_test_data` in `server.ts` gains a `DeletedUser` cleanup block placed between UserPrivate (line 545) and UserIdentity (line 552). Unconditional `.iter()` — SYSTEM is never evicted.
- 5 D-12 call sites migrated from inline `user ? user.displayName : \`User#${id}\`` to `resolveUserLabel(ctx, id).displayName`:

## Decisions Made

- **auditUpdate import removed from userDeletionHelper.ts** — The only use was in the replaced soft-delete block. After eviction, `auditUpdate` is no longer called anywhere in the file; removing the unused import keeps the file clean.
- **DeletedUser nuke block: no SYSTEM filter** — SYSTEM is never targeted by `performUserDeletion` (admin guards prevent deletion of the SYSTEM user), so the DeletedUser table can be cleared unconditionally. This matches the simpler pattern from RESEARCH.md §Pattern 7.
- **pUser variable removed at finalizationHelpers site 3** — After replacing `pUser ? pUser.displayName : \`User#${...}\`` with `resolveUserLabel(...)`, the `const pUser = ctx.db.User.id.find(p.userId)` fetch became unused and was removed.
- **targetUser variable removed at both lobbyLifecycle sites** — Same reasoning: the `.find()` fetch was only used for the ternary display name; both replaced with `resolveUserLabel` destructure.
