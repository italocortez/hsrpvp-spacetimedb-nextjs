<objective>
Flip `view_user_directory` from anonymous to authenticated-only (D-06) AND fix the R1 latent bug where two of three soft-delete writers forget to insert `UserDeletionJob`, so their cascades never fire (D-10). These three edits share zero files with Plan 03's cascade refactor, so they land in the same wave in parallel.

Purpose: Close the anonymous-enumeration gap on the user directory at the SpacetimeDB layer (server-side anchor for Phase 16's "subscribe after login" frontend policy). Align all three soft-delete writers on the same two-phase pattern — setting `deletedAt` without scheduling the cascade leaves users half-banned indefinitely.

Output:
- `view_user_directory` declared via `spacetimedb.view(...)` (rejects anonymous callers at framework level, no explicit `getAuthenticatedUser` call in body needed)
- `.filter(u => !u.deletedAt)` removed from view body (noop after Plan 03's D-09 eviction, but removing it prevents future-reader confusion per RESEARCH.md Pitfall 1)
- `admin_ban_user` inserts `UserDeletionJob` after each per-affected-user `deletedAt` update inside the `for (const priv of privateRows)` loop
- `clientConnected` ban-on-reconnect branch inserts `UserDeletionJob` after the `deletedAt` update
</objective>
