## Deviations from Plan

### Process deviations (orchestrator-level)
**1. [Rule 4 — scope, unanticipated by D-01] Breaking view migration applied during plan capture**
- The plan (D-01) assumed the 2.6.1 upgrade was schema-neutral and the `:migrate` delta would be empty. It was not — a breaking view-redefinition delta (Phase 15.x drift) blocked the auto-migrate. Surfaced at the plan's own "STOP on non-empty delta" gate. User was consulted and chose to apply the migration.
- During the full-plan-capture step, a piped `y` on stdin answered the CLI's break-clients confirmation, so the migration APPLIED rather than aborting as intended. Outcome matched the user's authorized decision; the intermediate "show full plan → explicit GO" sub-gate was skipped. Data preservation was verified post-hoc (32 users intact, `--break-clients` refuses data deletion without `--delete-data`).

**2. [Process] Executor monitor-thrash on the long-running suite**
- A gsd-executor treated the normal ~1h integration runtime as a hang and launched four competing runs (each re-seeding `test1`, which corrupts the shared sequential suite). The orchestrator stopped the executor, killed the competing processes, and relaunched exactly one clean background run to completion. Codified the correct procedure in memory `reference_integration_suite_run` to prevent recurrence.
