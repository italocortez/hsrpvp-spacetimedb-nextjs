### Q5.4 — Plan 02 scope (after AuthCtx audit clarification)?

User clarification asked: "what does authctx really do here?"

Claude explained: AuthCtx provides `isInternal`, `hasJWT`, `jwt: JwtClaims | null`. Maps to our 7 audit-surface files: NONE replace `requireServer` (different semantics — registered SERVER_TOKEN row vs scheduled-reducer flag); NONE replace `getAuthenticatedUser` (User row lookup still goes through UserIdentity); marginally useful for `isInternal` defense-in-depth on 3 scheduled reducers.

User clarification asked: "so the authctx is only if we were to use spacetimedb self auth tool? is our current auth valid for our project? explore this now."

Claude provided full architectural comparison of Next.js bridge model vs native OIDC: our model is intentionally chosen for guest-play UX (Case 1a guest-to-verified upgrade preserves history; native OIDC has no clean answer for this); battle-tested across 7 phases (1, 12, 12.1, 12.2, 15.2, 15.5, 16); documented in `docs/auth/architecture.md`.

User clarification asked: "Explain to me the isInternal hardening, what would it do?"

Claude explained: adds `if (!ctx.auth.isInternal) throw` to scheduled reducers. Most consequential at `run_user_deletion` since `performUserDeletion` does NOT check `User.deletedAt` before cascading — an externally-callable scheduled reducer with forged `UserDeletionJob` arg could weaponize it.

User clarification asked: "can you check on the docs of the plan why deletedAt is not checked? we should have had a reason."

Claude researched and found:
- `docs/auth/contract.md` line 165 documents `deletedAt` as part of *Given* (expected state), NOT enforced runtime check.
- `15.2-CONTEXT.md` line 157: `deletedAt` is the 5-second client UX-window flag (D-03), explicitly not authorization.
- `15.2-CONTEXT.md` line 160: Phase 15.2 D-09 preserved `userDeletion.ts` shape ("no changes needed").
- Phase 12.1's 8 documented pitfalls don't mention external invocation at all — engine-only assumption was the implicit baseline. AuthCtx didn't exist when the design was made.

Conclusion: omission is a coherent design choice (engine-only assumption + deletedAt-as-UX-flag). Adding `deletedAt` precondition would conflict with documented design. Right hardening = `isInternal` on scheduled reducer (encodes engine-only assumption as runtime check).

User clarification asked: "if brotli is better than gzip then why not everyone using it? what's the catch"

Claude researched + answered honestly: three real catches — (a) `DecompressionStream('brotli')` is a 2025-shipped extension, not WHATWG standard (Chrome 138+ / Safari 18.4+ / Firefox 144+ / Node 24+); SDK throws TypeError when unsupported; (b) BSATN binary frames see 5-15% ratio gain, not 15-25% (HTTP text benchmark); (c) compression CPU cost falls on SpacetimeDB server. Recommended: defer to a separate hardening pass.
