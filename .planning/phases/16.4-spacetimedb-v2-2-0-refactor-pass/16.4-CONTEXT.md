### Server Refactor — Table.clear() (SC#1)

- **D-09:** Plan 01 scope locked at **42 `Table.clear()` replacements** in `spacetimedb/src/reducers/server.ts → server_nuke_test_data`. Map:
  - 41 `nuke(table, name)` calls (lines 434–512) → `ctx.db.{Table}.clear()` — the helper iter()s all rows + deletes all; pure 1:1 conversion.
  - 1 inline DeletedUser block (lines 528–531) — no SYSTEM filter, full iter+delete → `ctx.db.DeletedUser.clear()`.
  - 3 SYSTEM-preserving blocks **stay as iter+filter+delete** (UserPrivate, UserIdentity, User — preserve `username='SYSTEM'` row by id).
  - `nuke()` helper (lines 418–427) **deleted** — no remaining callers.
  - Per-table `[NUKE] {name}: {count}` log lines **dropped** — no consumers (verified: scripts/nuke-test-data.ts only awaits the reducer; no log parser exists). Single `[NUKE] complete` log line preserved.
  - GC reducers (`performLobbyGc`, `performIdentityGc`, `hardDeleteLobby`) explicitly **NOT candidates** — they do per-row predicate / per-lobby filter deletes, not whole-table wipes. Plan 01 documents this in audit notes so future readers don't re-investigate.

### Server Refactor — AuthCtx Audit + isInternal Hardening (SC#2)

- **D-13:** Plan 02 scope = **AUDIT-NOTES file + `isInternal` hardening on 3 scheduled reducers + skill rule**. AUDIT-NOTES documents:
  - (a) Why `AuthCtx` does NOT replace `requireServer(ctx)` — different semantics: `isInternal` means "engine-dispatched scheduled reducer," NOT "the registered SERVER_TOKEN identity." Our `ServerIdentity` row check is a separate concept; `post-publish.ts` is an external WS client from the SDK's view (`isInternal: false`).
  - (b) Why `AuthCtx` does NOT replace `getAuthenticatedUser(ctx)` — our auth model is `ctx.sender → UserIdentity → User → role.tag` (project business logic), not JWT-claims-based. We don't use native OIDC at the engine; we use the Next.js bridge (`/api/auth/link-discord` → `server_link_provider`) for Discord OAuth, which is intentional for guest-play UX (see deferred for rationale).
  - (c) Why `deletedAt` stays as UX flag, NOT authorization gate — per 15.2 D-03 / 15.2-CONTEXT.md line 157, `deletedAt` exists for the 5-second client "your account is being deleted" notification window. Adding `if (!user.deletedAt) throw` inside `performUserDeletion` would change documented semantics + lock out future writers that legitimately skip the UX window.
  - (d) Why `isInternal` is the right hardening — matches Phase 12.1's documented engine-only assumption (8 pitfalls explicitly enumerated, none of which discuss external invocation; admin variants gated with `ensureModerator`, scheduled variants left ungated under that assumption). v2.2.0's `isInternal` lets us encode the assumption as a runtime check instead of relying on it implicitly.
- Plan 02 adds `if (!ctx.auth.isInternal) throw new SenderError('Forbidden: scheduled reducer; cannot be invoked externally.')` to:
  - `run_user_deletion` (`spacetimedb/src/reducers/userDeletion.ts`) — most consequential; protects against external callers passing forged `UserDeletionJob` args
  - `run_lobby_gc` (`spacetimedb/src/reducers/lobbyGc.ts`)
  - `run_identity_gc` (`spacetimedb/src/reducers/identityGc.ts`)
- AUDIT-NOTES file format mirrors 16.3-AUDIT-NOTES.md.
- 7 audit-surface files inspected (server.ts, profile.ts, lobbyGc.ts, identityGc.ts, cursor.ts, admin.ts, auth.ts) — only the 3 scheduled reducers above are productive sites; documented finding.

  **Notable but NOT adopted in 16.4 (with reasoning):**
  - **#4561 Brotli compression option** — `.withCompression('brotli')` is available on `DbConnection.builder()`. Project keeps **gzip default** for now. Real catches: (a) `DecompressionStream('brotli')` is a 2025-shipped non-standard extension (Chrome 138+ / Safari 18.4+ / Firefox 144+ / Node 24+); SDK throws `TypeError` at builder-time when unsupported, crashing connection setup on older browsers; (b) realistic ratio gain on BSATN binary frames is 5-15%, not the 15-25% commonly cited for HTTP text; (c) compression CPU cost falls on SpacetimeDB (maincloud) on the server side. Decision: do NOT adopt brotli in 16.4, do NOT capture as deferred (avoid implying future adoption). SKILL.md gets a single note: "`.withCompression('brotli')` exists in v2.2.0+ as an alternative to gzip; project has not adopted it."

  **Informational-only (auto-applied by SDK upgrade — Plan 03 / Plan 04 / SKILL note these in passing):**
