```typescript
export interface UseTableCallbacks<RowType> {
    onInsert?: (row: RowType) => void;
    onDelete?: (row: RowType) => void;
    onUpdate?: (oldRow: RowType, newRow: RowType) => void;
    /** Whether the subscription is active. Defaults to `true`. */
    enabled?: boolean;
}

export declare function useTable<TableDef extends UntypedTableDef>(
    query: Query<TableDef>,
    callbacks?: UseTableCallbacks<Prettify<RowType<TableDef>>>
): [readonly Prettify<RowType<TableDef>>[], boolean];
```

`enabled` lives in the SAME object as `onInsert/onDelete/onUpdate` — NOT a third arg, NOT a separate options bag.

    ```markdown
    ## Decision 9 — Layer-0 subscriptions are always-on; gated panels use useTable enabled

    GameDataProvider's 7 layer-0 subs (HsrCharacter, HsrLightcone, HsrCharacterCost, HsrLightconeCost, HsrSynergyCost, Archetype, HsrCharacterArchetype) stay always-on, no `enabled` prop. Service worker portrait/Spine prefetch + anonymous-page hydration depend on this data being unconditionally live. Gated UI panels (admin tabs, modals, etc.) pass `{ enabled: <boolean> }` as the 2nd arg to `useTable`.

    ### Scope

    | Site | Status |
    |---|---|
    | `components/features/game-data/components/GameDataProvider.tsx` (7 layer-0 subs) | NO change — always-on, confirmed |
    | `components/features/admin-view/components/UserManager.tsx` | Gates on `isActive === 'users'` (Phase 16.4 Plan 05) |
    | `components/features/admin-view/components/TableExplorer.tsx` | Gates on `isActive === 'tables'` (Phase 16.4 Plan 05) |
    | `components/features/admin-view/components/BulkUpsert.tsx` | NO useTable subscription — N/A |

    ### Rationale

    Gating layer-0 would reintroduce the "first frame missing portraits" hydration bug that the layer-0 subscription model was designed to prevent. The service worker prefetch (portrait + Spine assets) reads from the layer-0 tables on mount; if those subs were gated by route-state or visibility, the prefetch race would resurface. Cost: ~80 KB on wire (smaller than a single hero image, per Decision 1).

    Gated panels are a different cost story: the User table sub on `/admin-view` would otherwise fire on mount even when the User tab is not selected (the `display: none` pattern keeps the component mounted, so its subscription persists). Gating recovers that egress when admins are working in the Tables tab. Real measurable egress drop on the admin route.

    ### Implementation notes

    - The `enabled` prop lives in the 2nd-arg callback object alongside `onInsert/onDelete/onUpdate` (verified at `spacetimedb/node_modules/spacetimedb/dist/react/useTable.d.ts:1-10`). NOT a third arg, NOT a separate options bag.
    - Phase 16.4 Plan 05 committed this decision alongside the admin-tab refactor.
    - When `enabled` transitions `true → false`, the SDK tears down the subscription (no leaked socket); `false → true` re-establishes it.
    - For dynamic table accessors (e.g. `TABLE_MAP[selectedTable]` in TableExplorer), `enabled` gates whichever table is currently selected. Switching the dynamic key while `enabled === true` causes the SDK to swap subs.
    ```
