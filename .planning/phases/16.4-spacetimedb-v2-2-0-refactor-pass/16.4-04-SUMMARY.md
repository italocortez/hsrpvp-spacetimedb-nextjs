## Decisions Made

- **WebSocket factory shape — full SDK URL replication.** The SDK's withWSFn callback receives parsed args (URL, protocols, nameOrAddress, authToken, compression, lightMode, confirmedReads) and is expected to return a WebSocketAdapter (declared at dist/sdk/ws.d.ts). Replicated the SDK's openWebSocket URL construction (mint short-lived WS token via /v1/identity/websocket-token, build /v1/database/{name}/subscribe URL with compression=None query param) verified against dist/index.cjs:5033-5074. Plan 04's RESEARCH.md Example 6 sketched a 4-line pass-through; reality required ~130 LOC because the SDK does NOT pass a pre-formed URL — the factory builds it.
- **Compression forced to 'none'.** `.withCompression('none')` ensures logged frame sizes match on-wire BSATN bytes exactly. Eliminates gzip-ratio variability across runs and makes the baseline comparable run-to-run. Inbound frames carry a 1-byte compression tag (0=none/1=brotli/2=gzip); the factory strips the tag (`u8.subarray(1)`) before forwarding to the SDK.
- **Admin-token guard at startup.** Script exits 1 if `CAPTURE_WS_FIXTURE_TOKEN` is missing OR equal to `SPACETIMEDB_SERVER_TOKEN` (T-16.4-04-01 mitigation per RESEARCH.md OQ-2 — admin token would skew bandwidth profile because admin reducer surfaces are larger than guest surfaces).
- **rtk proxy wrapper for invocation.** Bare `npx tsx tools/capture-ws-frames.ts` is rewritten by the project RTK hook into a broken `npm` invocation (per `~/.claude/RTK.md` known limitation). Worked around by `rtk proxy "npx tsx tools/capture-ws-frames.ts"` — documented in summary.md reproduction section so future runners do not re-discover the issue.
