## Decisions Made

- **Empty-param reducer call shape: `callX()` not `callX({})`.** RESEARCH.md / PLAN.md context line 98 documented this verbatim (`ParamsType` collapses to `[]` when params is empty per `dist/sdk/type_utils.d.ts:7`), but the `<acceptance_criteria>` text in PLAN.md included a literal `loginAsGuestCall({})` grep check that contradicted the documented call shape. The acceptance text was authored as if `({})` would compile; it does not — `tsc --noEmit` produced `error TS2554: Expected 0 arguments, but got 1` at all 3 sites in useAuth.ts. Auto-fixed per Rule 1 (TypeScript error is a bug). The committed code uses `callX()` for empty-param reducers and `callX({...})` for param-bearing reducers (consistent with the verified SDK signature).
- **`useSpacetimeDB` import dropped from 4 of 5 sites.** UserManager, TableExplorer, BulkUpsert, and ProfileCard each had `getConnection` as their sole usage of `useSpacetimeDB()` — after the refactor those destructures became dead code, so the imports were dropped per PATTERNS.md guardrail. useAuth.ts retains the import (it has 5 OTHER destructures from useSpacetimeDB and `getConnection` is still needed for `readProfileFromConnection` direct table iter access). UserManager's import-drop landed in commit `1a12f75` (post-Task-2 cleanup caught during SUMMARY self-check).
- **`editingUserOriginalRole` added to saveEdit deps array (UserManager.tsx).** The original `[editState, getConnection]` deps array was actually missing `editingUserOriginalRole`, which is read inside the callback — a pre-existing stale-closure correctness gap silently masked because `editingUserOriginalRole` is a useMemo derived from `[editState, allUsers]` and editState already triggered re-render. The post-refactor deps `[editState, editingUserOriginalRole, adminUpdateUser]` close that gap as a side-effect of the refactor (Rule 2 — missing critical correctness).
- **Disk-only update for `notes/v09-frontend-subscription-strategy.md`.** Same reasoning as Plan 05: `notes/` is gitignored (.gitignore:54). Per CLAUDE.md "Gitignore Guardrail" — `git add -f` is forbidden. Disk edit applied; SKILL.md cross-reference IS committed for tracked breadcrumb.
- **No reducer-call refactor in app/api/auth/link-discord/route.ts.** D-15 hard constraint — server-side Next.js Route Handler using `getServerConnection()` (verified `lib/spacetimedb-server.ts:26`); React hooks do not apply. `git diff app/api/auth/link-discord/route.ts` returns empty.

**1. [Rule 1 — Bug] Empty-param reducer call shape: `callX()` not `callX({})`**

- **Found during:** Task 1 typecheck (after first edit pass on useAuth.ts).
- **Issue:** PLAN.md `<action>` Step 4 / Step 5 instructed me to call `loginAsGuestCall({})` and `deleteGuestAccountCall({})`, and the `<acceptance_criteria>` had matching literal grep checks. But the SDK's `useReducer<ReducerDef>(reducerDef)` returns `(...params: ParamsType<ReducerDef>) => Promise<void>`, where `ParamsType` collapses to `[]` (no args) when the reducer schema is empty (verified `dist/sdk/type_utils.d.ts:7`). `loginAsGuest` and `deleteGuestAccount` reducers have empty schemas (verified `src/module_bindings/login_as_guest_reducer.ts:13` exports `default {}`). Calling `loginAsGuestCall({})` produced 3 TypeScript errors: `error TS2554: Expected 0 arguments, but got 1` at lines 238, 333, 355 of useAuth.ts.
- **Fix:** Replaced `loginAsGuestCall({})` → `loginAsGuestCall()` and `deleteGuestAccountCall({})` → `deleteGuestAccountCall()` at all 3 sites. PLAN.md context line 98 actually documented this correctly ("ParamsType collapses to [] when params is empty, [params: T] otherwise — so empty-param reducers are called as callX()"); the contradiction was confined to `<action>` instructions and `<acceptance_criteria>` greps. The acceptance criteria are otherwise verifiable — the refactored sites match the *intent* of the criteria (useReducer adopted, conn.reducers calls dropped, getConnection null-checks dropped). The literal `loginAsGuestCall({})` grep check is the artifact that diverges from reality; I treated this as PLAN.md inaccuracy, not a behavioral deviation.
- **Files modified:** `components/features/auth/hooks/useAuth.ts` lines 238, 333, 355.
