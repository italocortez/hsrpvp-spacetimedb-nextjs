## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan 02's `ctx.senderAuth.isInternal` guard rejected legitimate engine-dispatched scheduled reducer invocations**

- **Found during:** Step A diagnostic isolation rerun (prior continuation `d2746ef`)
- **Issue:** SDK v2.2.0's `senderAuth` accessor unconditionally returns `isInternal: false` (the only `isInternal: true` factory `AuthCtxImpl.internal()` is unreachable from any code path that produces `ctx.senderAuth`). Plan 02's guards therefore rejected ALL invocations, breaking user-deletion cascade, lobby GC, and identity GC.
- **Fix:** Reverted the 3 guards (Step F1, commit `9c634bc`); updated regression sensor test text to document engine-level defense as operational truth (Step F2, commit `f24fd86`); rewrote SKILL.md rule (Step F3, commit `ead065d`); amended AUDIT-NOTES.md with reversal record (Step F4, commit `6515a59`).
- **Files modified:** see Files Created/Modified above
- **Verification:** Step F5 — user-deletion.test.ts 5/5 PASS (cascade restored); regression sensor 3/3 PASS (engine-level defense path still operative)
- **Committed in:** 4 commits (`9c634bc`, `f24fd86`, `ead065d`, `6515a59`) — atomic per-concern; revert + test + skill + audit
- **Categorization:** Plan 02 had introduced a real production regression that broke production cascade paths. This is Rule 1 (bug fix), executed as a multi-commit hotfix within Plan 07's scope per explicit user authorization.

**2. [Rule 3 - Blocking] `spacetime sql IN (...)` and `count(*)` without alias not supported on v2.2.0**

- **Found during:** Step F6 smoke probes
- **Issue:** Smoke probe 1 used `WHERE table_name IN ('lobby_member', 'match_session', 'chat_message')` (rejected: "Unsupported expression: ... IN (...)"). Smoke probe 2 used `SELECT count(*) FROM gc_result` (rejected: "Aggregate expressions must have column aliases").
- **Fix:** Split IN(...) into 3 separate per-table queries; aliased aggregate as `count(*) AS total`. Both probes succeeded post-workaround.
- **Files modified:** None (workaround applied at command line; documented in VERIFY-NOTES.md "Live smoke probes" section + deferred-items.md D-2)
- **Verification:** All 3 st_table queries return expected schema; gc_result count returns 0
- **Committed in:** Documentation captured in the Step F7 finalize commit
- **Categorization:** Rule 3 (blocking) — would have prevented the smoke probes from completing. D-2 in deferred-items.md captures the operator gap as informational; SKILL.md `### spacetime sql column name gotcha` is the natural extension point for a future codification pass (out-of-scope for 16.4).
