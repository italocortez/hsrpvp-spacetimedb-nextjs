## Decisions Made

- **Plan's "41 nuke-call replacements" count was a miscount (actual original = 49 nuke() calls).** Verified via git show on the pre-refactor commit — original file had 49 `totalDeleted += nuke(...)` lines. Final cleared-site count is therefore 50 (49 + 1 inline DeletedUser), comfortably exceeding the acceptance criterion's "at least 42" threshold. No deviation — the criterion was correct as written, only the count rationale was off.
- **Took the plan's "use as a statement, not as `const n = ...`" instruction at face value** even though `dist/lib/table.d.ts:159` actually declares `clear(): bigint`. The plan's stated convention (statement form, no return-value capture) is preferable for uniformity across all 50 sites and matches the plan's wording for the SKILL.md rule. This decision is documented in the SKILL.md rule itself: "TS declarations do NOT surface a row count from `clear()`; use it as a statement, not as `const n = ctx.db.X.clear()` (n would be untyped)." If the SDK declaration is later confirmed to be a stable surface, the SKILL rule can be relaxed in a future phase — but the **statement form is also a fine permanent convention** because it's simpler and removes the temptation to write per-site logging that would re-introduce the boilerplate the refactor eliminated.
- **SKILL.md insertion point: between `### CRUD operations (server)` and `### Accessor types`** — best topical placement per PATTERNS.md guidance ("place new rules in topical order: server-side rules near existing server sections (Reducers, CRUD)"). The new rule is a server-side CRUD operation, and this placement keeps related CRUD content adjacent.

## Issues Encountered

- **Stale SDK type comment in plan `<interfaces>` block.** The plan's `<interfaces>` block claims "TS declarations do NOT surface a row count" for `clear()`, but `spacetimedb/node_modules/spacetimedb/dist/lib/table.d.ts:159` actually declares `clear(): bigint;` (with JSDoc: "Returns the number of rows deleted, i.e., the return value of `this.count()` before this call."). This may have been true in an earlier v2.2.0-pre snapshot but is no longer accurate. Resolution: followed the plan's stated convention regardless (statement form is still a fine choice for the reasons above), but flagged in `## Decisions Made` so a future verifier can decide whether to relax the SKILL rule.
- **Acceptance criterion `npm run test:integration -- --run server-nuke` references a test file that does not exist.** Searched `test/` directory: no file matches `server-nuke`, `nuke`, or `server_nuke`. Resolved by relying on the structurally stronger checks: full `npm run test:typecheck` (passed clean) + 8 grep-based acceptance criteria (all passed). The nuke reducer's behavioral verification will land in Plan 07's maincloud republish + smoke gate per CONTEXT.md D-08 (which calls `admin_gc_lobbies` post-republish to confirm GC chain still works after Table.clear() refactor).
