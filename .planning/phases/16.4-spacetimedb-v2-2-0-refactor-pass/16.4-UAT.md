## Deferred for Future Phase — Admin-View Redesign

- **Test 5 finding: User-table double-subscription**
  When admin-view is redesigned, eliminate the redundancy between `app/(authed)/layout.tsx:71`'s permanent `SELECT * FROM user` and `UserManager.tsx:36`'s `useTable(tables.User, { enabled: isActive })`. SDK does not dedupe identical query strings (each `subscribe()` sends its own SubscribeMulti frame). Two paths: drop the layout sub and let panels own their own subs scoped to need, OR drop UserManager's useTable and rely on the layout sub as authoritative. Plan 05's gating pattern stays, but applies to non-redundant tables only.

- **Test 6 finding: TableExplorer dropdown mixes layer-0 and exclusive tables**
  TableExplorer's TABLE_MAP includes 6 tables already permanently subscribed at higher layers (User via layout, 5 HSR reference tables via GameDataProvider) and 6 tables exclusive to TableExplorer (Lobby, LobbyMember, MatchSession, MatchSessionStep, MatchSessionHistory, MatchSessionStepHistory). Picking a layer-0 table triggers a redundant double-subscribe with full InitialSubscription re-download (worst case: HsrCharacterCost ~5000 rows).
  Redesign options:
    (a) Skip subscribing in TableExplorer for tables already subscribed elsewhere — read directly from SDK cache via `ctx.db.<table>.iter()`. Gate `enabled` only on the exclusive set.
    (b) Add row-level granular subscriptions via query builder (`tables.X.where(...)`) or raw SQL WHERE — pushes filter/pagination predicate to the engine, drops InitialSubscription size to what's currently visible.
    (c) Add server-side admin views (`view_admin_<table>`) with predicate filtering on the server; client subs to the small view.
  Each subscribe in v2.2.0 = full re-evaluation + InitialSubscription with all matching rows; SDK has no delta-from-last-seen mechanism. Tab activation cost is dominated by the InitialSubscription payload, so granularity matters.
