# Phase 15.4 Plan 04: Test rewrites for draftMode shape — Summary

Rewrote six existing cost-table integration test files to operate on the new single `costs` struct + `draftMode` discriminator shape, added one new file (`synergy-auction-round-trip.test.ts`) for first-ever D-25a auction coverage, added explicit Pitfall 1 / 6 / 7 regression guards, and added per-draftMode validateKeys rejection tests. Full `npm run test:integration` suite green: 58 files / 615 tests / 0 failures in 3737s against maincloud.

## What Changed

### Task 1 — admin reducer test trio (commit `8a2ea79`)

- **cost-set-pk.test.ts**: full rewrite. New Pitfall 1 regression scenarios for both char 4-tuple and synergy 5-tuple — seeding Classic+Auction rows for the same (name, mode, csId) then upserting only the Classic row must leave the Auction sibling untouched. Also a structural presence check on `by_character_mode_and_set` / `by_lightcone_mode_and_set` / `by_tuple` accessors. 8 tests.
- **partial-update.test.ts**: heavy rewrite. Non-cost table scenarios (HsrCharacter / HsrLightcone partial update) preserved. Cost-table scenarios rewritten for the single `costs` column: null-on-UPDATE preserves the struct, Classic+Auction preserve independently (per-draftMode granularity), mergeForUpdate replaces wholesale on non-null. Added three validateKeys rejection tests (missing-draftMode on HsrCharacterCost / HsrLightconeCost / HsrSynergyCost). 9 tests.
- **seed-cost-extraction.test.ts**: full rewrite implementing D-18 scenarios under the new fan-out. Scenarios 15.4-1 (both sub-blocks → 2 rows), 15.4-2 (classic-only → 1 Classic row, NO Auction), 15.4-3 (auction-only → 1 Auction row, NO Classic), 15.4-5 (both absent → 0 rows). New D-25 coverage: synergy Auction emission, draftMode invariant on every default-seed cost row, synergy default seed includes at least one Auction row (D-13 first-ever). 7 tests.

All 24 tests in the trio pass against maincloud.

### Task 2 — lifecycle + round-trip + post-draft (commit `5a5a887`)

- **cost-set-lifecycle.test.ts**: full rewrite. Edit-draft-*-cost reducer calls now specify `draftModeTag`. Added per-draftMode edit tests (Classic + Auction) for char/lc/synergy. Publish assertion now expects 2 live rows per (name, mode) when draft had both draftModes — this is the explicit Pitfall 7 regression guard for all three publish phases (A=chars, B=lcs, C=synergies). create_cost_set D-20 clone test validates Auction synergy rows propagate from source set 0 through clone → publish to live. 14 tests (including isolated default-protection describe).
- **round-trip.test.ts**: full rewrite. Existing Phase 15 D-21a scenarios preserved (3-mode fan-out, default sentinel). New 15.4 assertions: every HsrCharacterCost/HsrLightconeCost default-seed row has draftMode ∈ {Classic, Auction}; HsrSynergyCost default seed has BOTH Classic and Auction rows (D-13 first-ever); numeric costModifier preserved through serialization; `costs` struct column serializes with all eidolon/superimposition keys present. 11 tests.
- **post-draft.test.ts**: minor update per plan. The existing `equip_lightcone` test's "costPaid=0 via absence" assertion stays valid under 15.4 (LC `in-the-night` has no HsrLightconeCost row at csId=0). Updated the one comment describing the lookup semantic to reference the new (lightconeName, gameMode, draftMode='Classic', costSetId) filter. Added a supplemental describe block `15.4 D-10/D-11 LC cost lookup` with 2 new tests — positive Classic read through the new 4-positional shape and negative Auction-only → Classic-filter-empty — verified via the public HsrLightconeCost subscription cache (equip reducer's in-reducer logic is exercised indirectly through the costPaid arithmetic in the existing tests). Non-cost post-draft tests (unchanged; 27 tests still green).

All 52 tests in the trio pass.

### Task 3 — synergy auction round-trip + phase-gate (commit `b8c3220`)

- **synergy-auction-round-trip.test.ts** (NEW): 5 tests covering the D-25a first-ever auction path:
  1. `admin_bulk_upsert` direct insert of an Auction synergy row (reads back with correct draftMode.tag + costModifier).
  2. Classic + Auction coexistence on identical (source, target, mode, csId) — 2 distinct rows.
  3. `edit_draft_synergy_cost` insert-then-update via 5-tuple match — verified by publishing the draft and observing exactly 1 live Auction row carrying the UPDATED modifier (not 2 rows; would be 2 if the 5-tuple missed draftMode).
  4. `publish_cost_set` materializes an Auction-only draft row to a live HsrSynergyCost row (first-ever auction materialization path).
  5. Structural presence of the `by_tuple` btree accessor on the client db table.

All 5 tests pass. Full `npm run test:integration` subsequently ran green: **58 files / 615 tests / 0 failures, 3737s**.

## Binding Accessor Casing (verified per Step 0)

Checked against `src/module_bindings/` before writing assertions:

| Kind | Surface | Style | Example |
|---|---|---|---|
| Reducer names | `admin.conn.reducers.*` / `h.call.*` | camelCase | `adminBulkUpsert`, `editDraftSynergyCost`, `publishCostSet`, `createCostSet`, `lockCostSet`, `unpublishCostSet`, `deleteCostSet` |
| Row column fields | Row object keys | camelCase | `sourceName`, `gameMode`, `draftMode`, `costSetId`, `costModifier` |
| Enum tag | `row.gameMode.tag` / `row.draftMode.tag` | PascalCase string literal | `'Classic'`, `'Auction'`, `'MemoryOfChaos'` |
| Multi-col btree accessors | `admin.conn.db.<Table>.<accessor>.filter(...)` | snake_case | `by_character_mode_and_set`, `by_lightcone_mode_and_set`, `by_tuple`, `cost_set_id` |
| Reducer arg keys | bindings default types | camelCase | `costSetId`, `draftModeTag`, `gameModeTag`, `costsJson`, `tableName`, `jsonData` |

Notes carried forward:
- A2_FALLBACK_ITER applies: btree `.filter([..., enumStruct, ...])` unsupported with tagged-union values. Server-side admin / publish / edit reducers all use `iter() + predicate`; tests mirror this via `[...db.iter()].filter(predicate)`. Btree accessors are declared and surfaced (verified in `cost-set-pk.test.ts` sanity test) for future non-enum-struct filter migrations.
- `loginAsGuest` + `serverLinkProvider` are the only reducers with unusual casing (`loginAsGuest`, `serverLinkProvider`) — unchanged from prior phases.
