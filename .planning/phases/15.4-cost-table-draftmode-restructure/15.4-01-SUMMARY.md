# Phase 15.4 Plan 01: Backend schema + reducers + bindings + docs — Summary

One-line summary: Rewrote 6 cost tables to use a single `costs` struct + `draftMode: DraftMode` discriminator (replacing `classicCosts` + `auctionBaseBid`), extended PK tuples and multi-col btree indexes with `draftMode`, rewrote 5 cost-touching reducers for 4/5-tuple match, removed PkTest probe artifacts, published with `--delete-data=on-conflict`, regenerated both `module_bindings/` directories, and updated both architecture docs — all in one atomic backend-only plan. Frontend/seed/tests are intentionally left broken for Plans 02/03/04.

## What Changed

### Task 1 — Schema rewrite (commit `cdc637a`)

All 6 cost tables transformed in-place:

| Table | PK tuple | New columns | Indexes |
|-------|---------|-------------|---------|
| HsrCharacterCost | `[characterName, gameMode, draftMode, costSetId]` (decorative) | `draftMode: DraftMode`, `costs: EidolonCost` | `cost_set_id`, `by_character_mode_and_set` (4-col) |
| HsrLightconeCost | `[lightconeName, gameMode, draftMode, costSetId]` (decorative) | `draftMode: DraftMode`, `costs: SuperimpositionCost` | `cost_set_id`, `by_lightcone_mode_and_set` (4-col) |
| HsrSynergyCost | `id: u32 PK autoInc` (kept — only real engine constraint per D-06) | `draftMode: DraftMode` between `gameMode` and `costModifier` | `source_mode` (3-col, extended), `target_name`, `cost_set_id`, **new `by_tuple` (5-col)** |
| CostSetDraftCharacter | `[costSetId, characterName, gameMode, draftMode]` (decorative) | `draftMode`, `costs: EidolonCost` | `cost_set_id`, `by_set_character_and_mode` (4-col) |

## A2 Decision

**A2_FALLBACK_ITER.** The btree `.filter([name, gameMode, draftModeStruct, csId])` pattern with a tagged-union enum struct as a filter value is unsupported in the current SpacetimeDB bindings layer — verified by the pre-existing comment at `admin.ts:497` from Phase 15.1 ("Tuple-filter with enum struct is unsupported (RESEARCH.md A2); use iter() fallback"). This plan extends that precedent:

- `admin.ts` HsrCharacterCost / HsrLightconeCost / HsrSynergyCost bulk-upsert cases: `iter() + predicate` with extended predicate including `e.draftMode.tag === r.draftMode`.
- `postDraft.ts` LC lookup: switched from multi-arg btree filter to `cost_set_id.filter(csId) + predicate.find()` with `r.draftMode.tag === 'Classic'`.
- `draftClassic.ts` + `draftAuction.ts` readers: stay on `cost_set_id` filter + in-memory `.find()` (unchanged from prior iteration).

Error encountered: none at TypeScript compile time (the code path was not attempted with enum struct filter — decision made by established precedent from the Phase 15.1 iteration). The btree indexes themselves (`by_character_mode_and_set` 4-col, `by_tuple` 5-col) remain declared and usable by views / client subscriptions / future non-enum-struct filters.

**Implication for Plan 04 (test rewrite):** Assertions for cost-set-pk.test.ts should use the `iter() + find()` pattern and verify tuple match via `[...ctx.db.HsrCharacterCost.iter()].filter(...)` rather than `by_character_mode_and_set.filter([name, gameMode, draftMode, csId])`. The 4/5-col btree indexes are present for structural correctness but are not the active admin-write path.
