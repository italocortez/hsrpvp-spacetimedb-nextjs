# Phase 15.4: Cost-table draftMode restructure — Pattern Map

**Mapped:** 2026-04-14
**Files analyzed:** 27 (6 tables + 6 reducers + 2 seed + 2 templates + 1 README + ~10 frontend)
**Analogs found:** 27 / 27 (100% — this is a restructure of existing code, every target has a direct sibling or current-self analog)

Every file modified in 15.4 is an evolution of an existing file in the same repo. The pattern-copying operation is dominated by "copy the sibling table's new shape" and "copy the current file's own structure with mechanical field substitutions." Analogs come in two flavors:

- **Same-self analog:** The current state of the file itself, modified to the D-## spec. Used where no cleaner sibling exists (e.g. `admin.ts` bulk upsert HsrSynergyCost case — the char/lc siblings use composite-PK delete+insert, synergy uses `id.update()`, so the current synergy case is the right analog for the restructured synergy case).
- **Sibling analog:** A peer file that already exhibits the target shape at one end (e.g. `HsrCharacterCost` is the lead table; `HsrLightconeCost` and the draft-character table mirror it one-for-one).

## Shared Patterns

### Audit columns (cross-cutting, no change)

**Source:** `spacetimedb/src/helpers/auditColumns.ts` (referenced ubiquitously).

**Pattern:** Every insert uses `...auditInsert(ctx, userId)`; every update uses `...auditUpdate(ctx, existing, userId)`. All 6 cost tables keep the 4 audit columns at the end of their column map. No 15.4 change to this pattern — the spreads carry through naturally because we preserve the rest of the row with `...existing` in update branches.

### Enum tagged union struct passing

**Source:** established throughout `admin.ts`, `costSetManagement.ts`, `draftAuction.ts`.

**Pattern:** Enums are declared as `t.enum(...)` in `types/enums.ts` and referenced in columns via the constant (e.g., `DraftMode`). At runtime:
- **Insert:** pass the struct object `{ tag: 'Classic', value: {} } as any`.
- **Filter predicate:** compare `row.draftMode.tag === 'Classic'` (string comparison on `.tag`).
- **Btree filter positional (assumption A2):** pass the same struct object in the filter array; if this fails in practice, fall back to `cost_set_id` btree + `.find()` predicate.

### Partial-update via `mergeForUpdate`

**Source:** `admin.ts` bulk-upsert cases (visible in the HsrCharacterCost case L509-514, HsrLightconeCost, HsrSynergyCost).

**Pattern:** Preserves existing values where incoming is null (15 D-08 partial-update). Applied identically to 15.4 — the `*_FIELDS` arrays shrink to `['costs']` for char/lc (down from `['classicCosts', 'auctionBaseBid']`), stay as `['costModifier']` for synergy.

### Composite-PK delete-then-insert upsert

**Source:** `costSetManagement.ts:edit_draft_character_cost` L160-170 (current draft-char delete+insert pattern); `admin.ts` HsrCharacterCost L516-524 (live-char delete+insert).

**Pattern:** Because composite `primaryKey` declarations are decorative (D-06 finding), there's no PK accessor for direct update. Pattern is `ctx.db.T.delete(existing)` then `ctx.db.T.insert({ ...new row, ...auditUpdate(ctx, existing, userId) })`. Preserved exactly for 15.4, just with new column shape.

### `?? 0` / `if (!row) return 0` reader pattern

**Source:** `draftAuction.ts:getCharacterBaseCost` L59, `postDraft.ts` L52-55 (fallback costSetId chain).

**Pattern:** Row absence → return 0, never throw. Reader-level silent zero lives across Phase 15 D-15 + 15.1 D-15 + 15.4 D-10. Applies identically to all three readers in this phase.

### JSON-string reducer arg parse + validate

**Source:** `costSetManagement.ts:edit_draft_character_cost` L136-152.

**Pattern:** Cost payloads arrive as `t.string()` args, `JSON.parse()` in a try/catch, throw `SenderError` with specific field message on parse failure, validate each numeric field. 15.4 D-16/D-17 collapses the dual-JSON pattern to single-JSON for char/lc (`costsJson` parses to `EidolonCost` or `SuperimpositionCost`); synergy D-18 replaces JSON with raw `t.f32()` because payload is a single scalar.

### Pascal-case enum tag in snake-case template fan-out

**Source:** `scripts/seed-data.ts:normalizeCharacterCosts` — `const gameMode = snakeToPascalMode(rawMode)`.

**Pattern:** Template keys (`memory_of_chaos`, `classic`, `auction`) are snake/lowercase; DB enum tags are PascalCase (`MemoryOfChaos`, `Classic`, `Auction`). The `draftMode: 'Classic' | 'Auction'` string passed to `admin_bulk_upsert` follows this convention (PascalCase string arg, wrapped to struct `{ tag, value }` in the insert). Extended uniformly to all three seed transforms.

### `--delete-data` publish + post-publish.ts local reset

**Source:** `memory/feedback_post_publish_only.md` + Phase 15.1 execution history.

**Pattern:** `spacetime publish --delete-data=on-conflict` triggers full table wipe on schema change; `scripts/post-publish.ts --clear-database` reseeds from `test/data/*.json` via `admin_bulk_upsert`. Applied identically for 15.4 cutover (D-22). Never call `register_server` manually.
