# Phase 16.1: CSS module hygiene - Context

**Gathered:** 2026-04-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Retroactive R8 component-hygiene enforcement for the 6 known CSS import violations surfaced during Phase 16 UAT Test 7:

- 5 team-builder components (`Teamslot`, `TeamRoster`, `SynergyDisplay`, `LoadoutDropdown`, `LoadoutControls`) currently import from `@/app/(public)/teambuilder/page.module.css` (leaf → trunk inversion). Each gets a co-located sibling `.module.css`; `page.module.css` retains only rules applied inside `page.tsx` itself.
- 1 cross-feature import: `components/features/costs/components/LightconeCostTable.tsx` imports `@/components/features/drafting/components/CharacterPool.module.css` (4 classes: `filters`, `paths`, `searchBar`, `clearButton`). Resolved via duplication, not shared extraction.
- Codebase-wide audit for any other `components/**/*.tsx` importing `@/app/**/*.module.css` — fix every occurrence.

**In scope:** The 4 ROADMAP success criteria — zero `from '@/app/...module.css'` in `components/`, no cross-feature CSS imports, build stays within ±5% bundle size, no "preload not used" warning at `/costs` + `/teambuilder` in prod start.

**Out of scope:**
- Creating `components/shared/styles/` (threshold ≥20 identical lines × ≥3 sites not met; defer to the phase that first hits it).
- ESLint rule enforcing the convention (defer per Phase 16 D-24 pattern — doc + grep is the enforcement surface; reopen on repeat PR-review miss).
- Any visual redesign. Pure hygiene refactor; zero user-observable change intended.
- Any refactor outside the 6 violating imports + their partition.

<decisions>
## Implementation Decisions

### Partition rule (what stays, what moves, what dies)

- **D-01:** `page.module.css` retains ONLY classes applied inside `page.tsx` itself. After the sweep, that is only `.teamBuilder` (applied at `app/(public)/teambuilder/page.tsx:48`). Every other class migrates to whichever component applies it via `styles.X`. Crisp rule enforceable with `grep` during review: "className location = CSS location."

- **D-02:** Dead rules are deleted during migration, not relocated. A class is dead if `grep -rn "styles\.<className>"` returns zero hits across `app/`, `components/`, `lib/`. Confirmed dead in `page.module.css`: `.main`, `.confirmation*` (confirmationTitle, confirmationMessage, confirmationActions, confirmationCancel, confirmationConfirm), `.dangerous`, `@keyframes grow-fade-in`, `@keyframes spin`. Deletions listed explicitly in the sweep commit message for audit.

- **D-03:** `@keyframes` move with their consumer. CSS Modules scope keyframes per file, so a keyframe in a different module than its `animation:` consumer silently fails. Live migration: `@keyframes fade-in` → `Teamslot.module.css` (consumed by `.imposition` at page.module.css:175). Dead keyframes (grow-fade-in, spin) are deleted per D-02.

- **D-04:** `@media` responsive blocks migrate with the base class they override. Current responsive block at `page.module.css:545-549` overrides `.charactersContainer` → moves to `TeamRoster.module.css` alongside the base rule. Any override for `.path` → moves to `Teamslot.module.css`. No cross-file responsive overrides survive.

- **D-05:** Sibling naming matches existing project convention: PascalCase mirroring the component file (`Teamslot.tsx` → `Teamslot.module.css`). Same pattern already in `components/features/drafting/components/CharacterPool.module.css` and `components/features/costs/components/CharacterCostTable.module.css`.

### Cross-component cascade resolution

- **D-06:** The single cross-file cascade `.roster:hover .clearButton { opacity: 1 }` (page.module.css:106) resolves via JS-driven hover state, NOT `:global` or cascade preservation. `TeamRoster` tracks hover via `onMouseEnter`/`onMouseLeave` on its root container, passes `isRosterHovered` prop into each `Teamslot` child. `Teamslot` applies a conditional class that reveals `.clearButton { opacity: 1 }`. Matches existing UX exactly (clear-button appears when pointer enters the roster, not per-slot). Adds ~4 lines state + prop wiring; survives the CSS module scope boundary cleanly.

- **D-07:** All other `:hover`, `:active`, `:disabled`, descendant (`>`, space), and `option`-descendant selectors in `page.module.css` are self-contained within a single component after partition. No further cascade resolution work needed. Verified by enumerating all compound selectors (page.module.css:106-515).

### Cross-feature CSS duplication (LightconeCostTable)

- **D-08:** `LightconeCostTable.tsx` stops importing `@/components/features/drafting/components/CharacterPool.module.css`. The 4 used classes (`filters`, `paths`, `searchBar`, `clearButton`) are duplicated into `components/features/costs/components/LightconeCostTable.module.css` (new file), scoped with whatever names make sense locally. Rationale: (a) only 1 consumer outside drafting, (b) ROADMAP rule "prefer duplication; extract to `components/shared/styles/` only when ≥20 identical lines × ≥3 sites" — this is 1 site × 4 classes, well under the threshold, (c) drafting is free to evolve its pool styles without unrelated breakage in costs, and vice versa.

- **D-09:** `CharacterPool.module.css` is not edited by this phase. Only LightconeCostTable.tsx changes on the drafting side (the import line is removed; no other code touches drafting).

### Verification and commit structure

- **D-10:** Six commits + one sweep, per-component atomic:
  1. `refactor(team-builder): co-locate Teamslot styles` — moves Teamslot classes + `@keyframes fade-in` from page.module.css to new `Teamslot.module.css`, updates import, adds `isRosterHovered` prop stub.
  2. `refactor(team-builder): co-locate TeamRoster styles + hover state` — moves TeamRoster classes + `@media` override for `.charactersContainer`, wires `onMouseEnter`/`onMouseLeave` + propagates `isRosterHovered` to children.
  3. `refactor(team-builder): co-locate SynergyDisplay styles`
  4. `refactor(team-builder): co-locate LoadoutDropdown styles`
  5. `refactor(team-builder): co-locate LoadoutControls styles`
  6. `refactor(costs): duplicate drafting styles into LightconeCostTable module` — removes the cross-feature import.
  7. `chore(team-builder): sweep page.module.css dead rules + verify grep` — deletes dead classes (`.main`, `.confirmation*`, `.dangerous`, dead keyframes), runs the 2 grep success-criteria assertions, confirms `npm run build` is clean, confirms prod-start console on `/costs` + `/teambuilder` has no "preload not used" warning.

- **D-11:** After each of commits 1–6, the planner/executor runs `npm run dev`, navigates to `/teambuilder` (for commits 1–5) or `/costs` (for commit 6), and visually verifies the feature the commit touched: hover reveals clear-button, drag/drop works, loadout dropdown opens and mini-grid previews render, synergy pairs display, cost tables render. No screenshot automation — human eye is the baseline. Regression in a single commit = bisect by commit; no cross-commit diff hunt.

- **D-12:** Bundle size compared to Phase 16 baseline at the sweep commit only. `npm run build` output captures First Load JS; plan documents the baseline number it observed before starting. Fails the plan if delta exceeds ±5%.

### Documentation

- **D-13:** `docs/frontend/component-hygiene.md` (shipped in Phase 16 D-23) gains a new rule with Good/Bad examples:

  > **Rule: Component CSS is co-located with the component file.**
  >
  > Good: `components/features/team-builder/Teamslot.tsx` + `components/features/team-builder/Teamslot.module.css` as siblings.
  > Bad: component imports `@/app/<route-group>/<path>/page.module.css`. Page CSS holds page-wrapper rules only; leaf components MUST NOT import from trunk.
  > Bad: component imports `@/components/features/<other-feature>/*.module.css`. If a rule is genuinely shared across features, duplicate it locally; extract to `components/shared/styles/` only when ≥20 identical lines repeat across ≥3 sites.

  Placement: new Rule 6 under the existing 5 rules from Phase 16 (keeps rule ordering stable). Commit message on the sweep commit references the doc update.

### Claude's Discretion

- Exact classname renames when a class moves to a new module (e.g., whether `.roster` stays `.roster` in `TeamRoster.module.css` or becomes `.container` — stylistic, no external impact).
- Exact prop name for the hover signal from TeamRoster → Teamslot (`isRosterHovered` is the working name; any clear equivalent is fine).
- Whether the 4 duplicated classes in `LightconeCostTable.module.css` keep drafting's names or get renamed locally. Plan picks what reads cleanest at the LightconeCostTable call site.
- Whether Area 3 verification catches a regression and requires a revert + re-do, or whether a forward-fix commit is acceptable. Default: forward-fix unless regression is in commit 7 (sweep), in which case revert the sweep and re-attempt.
- Precise wording of the new R8 rule's Good/Bad examples in the doc.

### Established Patterns
- **CSS Modules scope per file** — keyframes, `:global`, descendant selectors, `:hover` chains all scope to one file. Forced partition of `@keyframes fade-in` (D-03) and re-homing of responsive `@media` blocks (D-04) follows from the invariant, not a new convention.
- **Hover-reveal via parent state + child class** — not a widely used pattern in this codebase yet (`useAuth` uses refs for hover-like states, but not on a DOM-parent-to-child signal). D-06 introduces it; Phase 17+ may pattern-match.
- **Styling-tool-agnostic primitives** — Phase 16 D-25 established that new primitives use stdlib React + Next only (no HeroUI, no Tailwind). Phase 16.1 is pure CSS Modules; fully compliant.

### Integration Points
- **`page.tsx`** — single className (`styles.teamBuilder`) after partition. No behavior change; just a shrunk CSS module.

- **`LightconeCostTable.tsx`** — gains a new local `.module.css`, drops the cross-feature import. Classnames in the JSX `className={poolStyles.X}` change to `className={styles.X}` (or whatever local naming D-08's "local naming for readability" produces).

<specifics>
## Specific Ideas

- **Dead CSS is hygiene too.** The discussion surfaced that `.main`, `.confirmation*`, `.dangerous`, `@keyframes grow-fade-in`, `@keyframes spin` are all unused. The phase deletes them during migration (D-02). This is NOT scope creep — removing dead CSS from a file we're already partitioning is the same hygiene umbrella as fixing the imports.
- **User's engineering-first trust on remaining gray areas.** After the four explicit discussion areas, user explicitly said "if you see any gray areas, use what's best from web engineering perspective to do" — captured as Claude's discretion on the @keyframes co-location, @media responsive placement, shared-directory deferral, ESLint deferral, and sibling naming. These are locked in decisions above, not open for planner re-litigation.
- **No visual change.** The refactor is mechanical: same CSS rules, same classNames in JSX (just different `styles.` source file). The one real behavioral pattern change is D-06 JS hover state, and even that is designed to preserve exact visual behavior.
- **JS-driven hover is correct for cross-component reveal.** `:global` leaks names, `.slot:hover` shifts the hover semantic from "roster hover" to "per-slot hover" (breaks in the gap between slots), DOM restructure has unknowable drag/drop impact. JS state is the boring, durable answer.

</specifics>

The rule bodies are not identical (different clamps + dimensions) and only exist in 2 components, so duplication is the right answer today. Revisit only if a third "mini slot" consumer appears.
