## Decisions Made

- **No class renames.** Preserving `styles.X` call sites means Task 2 is a mechanical import-path swap + block deletion. Claude's Discretion permitted renames but none were needed — and renames would have violated the "smallest change" editing behavior from CLAUDE.md. Matches Plan 04 precedent.
- **Hover variants migrate with their base class.** `.clearBtn:hover` and `.menuBtn:hover` moved in the same commit as their respective base rules (Task 1). CSS Modules scope pseudo-class selectors per file just like regular class selectors; the `:hover` rules in the new module behave byte-identically to their pre-move form. Splitting base + pseudo across commits would leak cross-file cascade during the interval — same correctness risk class as @keyframes in Plan 01 and pseudo-elements in Plan 04.
- **Task 2 bundles page.module.css rule deletion with the TSX import swap.** Same atomicity rationale as Plans 01-04. Two separate commits would leave an intermediate state where LoadoutControls.tsx imports `./LoadoutControls.module.css` while the 9 controls classes still live in page.module.css — double specificity, class duplication risk, and a brief window where a build might resolve against the stale rules.
- **Outer `/* ═══ Controls ═══ */` section header deleted (not migrated).** The entire new module IS the controls; the triple-bar file header at the top (`LoadoutControls — CSS Module`) already establishes scope. Migrating the outer header would be redundant. The inner `/* ── Header (name + edit) ─── */` and `/* ── Controls content (action buttons) ─── */` sub-section comments WERE preserved — they group logical sub-clusters within the module.
- **Plan line-number drift accepted as non-deviation** (5th plan in a row). Plan was authored citing page.module.css lines 211-298 (original pre-phase geometry); at execution time, after Plans 01+02+03+04 had removed 170+28+24+150 = 372 lines, the Controls block lived at 20-111. Rule content was byte-identical; edits anchored to section comments (`/* ═══ Controls ═══ */` / `/* ═══ Confirmation Modal ═══ */`) and rule names, not line ranges.
