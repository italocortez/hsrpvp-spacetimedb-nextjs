## Decisions Made

- **No class renames.** Preserving `styles.X` call sites means Task 2 is a mechanical import-path swap + block deletion. Claude's Discretion permitted renames but none were needed — and renames would have violated the "smallest change" editing behavior from CLAUDE.md.
- **Pseudo-elements migrate with their base class.** `.rostersList::before`, `.dropdownHeader::before/::after`, `.selectButton:hover`, `.teamOption:not(:disabled):hover`, `.teamOption:disabled` all moved in the same commit as their respective base rules. No cross-file pseudo-element cascade — CSS Modules scope pseudo-element selectors per file just like regular class selectors; the `::before` on `.rostersList` in the new module is identical in behavior to the pre-move form.
- **Task 2 bundles page.module.css rule deletion with the TSX import swap.** Same atomicity rationale as Plans 01, 02, 03. Two separate commits would leave an intermediate state where LoadoutDropdown.tsx imports `./LoadoutDropdown.module.css` while the 13 dropdown classes still live in page.module.css — double specificity, class duplication risk, and a brief window where a build might resolve against the stale rules.
- **Outer `/* ═══ Loadout Dropdown ═══ */` section header deleted (not migrated).** The entire new module IS the dropdown; the triple-bar file header at the top (`LoadoutDropdown — CSS Module`) already establishes scope. Migrating the outer header would be redundant. The inner `/* ── Mini-grid inside loadout dropdown ─── */` sub-section comment WAS preserved — it groups the 5 mini-* classes within the module.
- **Plan line-number drift accepted as non-deviation** (same as Plan 03). Plan was authored citing page.module.css lines 300-448 (original pre-phase geometry); at execution time, after Plans 01 + 02 + 03 had removed 170 + 28 + 24 = 222 lines, the dropdown block lived at 113-261. Rule content was byte-identical; edits anchored to rule names + section comments, not line ranges.
