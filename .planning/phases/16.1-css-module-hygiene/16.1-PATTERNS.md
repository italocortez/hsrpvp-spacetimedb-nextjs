### `components/features/team-builder/Teamslot.module.css` (new — co-located sibling)

**Analog:** `components/features/drafting/components/LightconeSelector.module.css`

**File header comment convention** (lines 1–10 of LightconeSelector.module.css):
```css
/* ═══════════════════════════════════════════════════════════════════
   LightconeSelector — CSS Module
   
   Parent components (TeamSlot) control hover-triggered visibility of
   the search bar and LC art blur via data-attributes on the slot
   wrapper, allowing this module to remain self-contained.
   ═══════════════════════════════════════════════════════════════════ */
```
Use the same triple-bar header, substituting `Teamslot — CSS Module` and a brief note about `isRosterHovered` prop.

**`:global()` usage in analogs** (LightconeSelector.module.css lines 57–70 — the only legitimate use in components/):
```css
:global([data-slot-hover="true"]) .searchBar,
.inputWrapper:focus-within .searchBar {
  max-height: 2.5rem;
}
```
**Do NOT use `:global()` in any of the 5 new team-builder modules.** `LightconeSelector` uses it to respond to a `data-*` attribute set by a parent; the clearButton hover reveal uses JS state (D-06) instead, so no `:global()` is needed. The only `:global(...)` appearance in `page.module.css` is line 137 (a commented-out block) — ignore it.

**`@keyframes` co-location** — keyframe must live in the same file as the class that consumes it. Pattern from `CharacterPool.module.css` header (lines 1–9):
```css
/* - All animation keyframes use :global to avoid double-hashing. */
```
**Do NOT follow this note for the new modules.** CharacterPool was migrated from plain CSS; its `:global` on keyframes is legacy. The new `Teamslot.module.css` must define `@keyframes fade-in` as a plain (locally-scoped) keyframe alongside `.imposition`. Next.js 15 CSS Modules scope keyframe names per-file; the consumer (`.imposition { animation: fade-in ... }`) and the keyframe definition must be in the same file.

**Hover-reveal pattern** — two CSS classes in `Teamslot.module.css`, driven by a `isRosterHovered` prop passed from `TeamRoster`:
```css
/* page.module.css lines 92–111 — source of truth before split */
.clearButton {
  /* ... existing styles ... */
  opacity: 0;
  transition: all 200ms ease;
}
/* NEW class added alongside clearButton: */
.clearButtonVisible {
  opacity: 1;
}
```
The `.roster:hover .clearButton { opacity: 1 }` rule at `page.module.css:106` is **not** migrated as a CSS rule. It is replaced by the `.clearButtonVisible` class applied conditionally in JSX.

## Critical Gotchas for Planner

**1. `@keyframes fade-in` must go to `Teamslot.module.css` in commit 1.**
Source at `page.module.css` around line 520. Consumer is `.imposition { animation: fade-in ... }`. CSS Modules scopes keyframe names per file — cross-file animation reference silently fails. The keyframe and its consumer must be in the same `.module.css`.

**2. `@media` block at `page.module.css:545–561` spans two components.**
`.charactersContainer` override → `TeamRoster.module.css`. `.path`, `.verticals`, `.clearButton` overrides → `Teamslot.module.css`. The `@media` block at `page.module.css:563–570` (`.portrait`, `.clearButton`) → `Teamslot.module.css`.

**3. `.roster:hover .clearButton { opacity: 1 }` at `page.module.css:106` is NOT migrated as CSS.**
It is replaced by the `isRosterHovered` JS prop pattern. The CSS analog is `.clearButtonVisible { opacity: 1 }` in `Teamslot.module.css`.

**4. `LightconeCostTable.tsx` has TWO style imports today (lines 10–11).**
Line 10 = `poolStyles` (cross-feature, remove). Line 11 = `styles` from `./CharacterCostTable.module.css` (same-feature, keep for `rarityBadge`). The new `LightconeCostTable.module.css` carries only the 4 filter classes; introduce as `filterStyles` alias to avoid shadowing `styles`.

**5. `components/shared/styles/` does not exist.**
Only `components/features/` and `components/globals/` exist under `components/`. Do not create `components/shared/` in this phase (deferred per CONTEXT.md).

**6. `:global()` is used in `LightconeSelector.module.css` and `CharacterPool.module.css` (header comment mentions it for keyframes).**
Do not carry `:global()` into any new team-builder module. The only `:global` in `page.module.css` is a commented-out block (line 137). None of the 5 new modules need it.

**7. `composes:` exists in `ProfileCard.module.css` only.**
Not used in any team-builder or costs module. Do not introduce it in new files.
