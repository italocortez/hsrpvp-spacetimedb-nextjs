## Directory Purposes

**`app/(authenticated)/`:**
- Purpose: Pages that gate on user authentication at the layout level
- Key files: `admin-view/layout.tsx` (role === 'Admin' guard), `lobby/page.tsx`, `profile/page.tsx`
- Note: Auth gates are client-side checks using `useAuthContext()`. Route group name has no URL impact.

**`app/(game)/`:**
- Purpose: In-game screen routes (draft interface)
- Key files: `draft/[matchId]/page.tsx` — dynamic route for a specific match

**`app/(landing-page)/`:**
- Purpose: Public pages not requiring login
- Key files: `costs/page.tsx`, `teambuilder/page.tsx`

**`app/api/auth/`:**
- Purpose: NextAuth OAuth endpoints and the trusted Discord linking bridge
- Key files: `authOptions.ts` (configure Discord provider), `link-discord/route.ts` (POST handler)

**`components/features/`:**
- Purpose: All feature-specific logic, hooks, and components organized by domain
- Convention: Each feature directory has `components/` for UI and `hooks/` for stateful logic

**`components/globals/`:**
- Purpose: UI primitives and layout components shared across all features
- Key files: `layout/Header.tsx`, `layout/Footer.tsx`, `modals/DeleteConfirmModal.tsx`, `icons/Icons.tsx`

**`components/features/types/enums.ts`:**
- Purpose: Frontend mirror of server-side enum types. All valid enum values are exported as `const` arrays (e.g., `PATH_VARIANTS`, `ELEMENT_VARIANTS`) for validation and iteration.

**`lib/`:**
- Purpose: Non-React shared utilities for both client and server contexts
- Key files: `spacetimedb.ts` (client config), `spacetimedb-server.ts` (server singleton)

**`src/module_bindings/`:**
- Purpose: Auto-generated SpacetimeDB TypeScript bindings
- Generated: Yes — run `spacetime generate` after every backend publish
- Committed: Yes
- Do not hand-edit. All edits are overwritten on next generation.

**`spacetimedb/src/`:**
- Purpose: The SpacetimeDB backend module source
- Key pattern: `schema.ts` imports all table definitions and passes them to `schema({...})`. `index.ts` imports `schema.ts` and all reducer files, then exports everything.

## Naming Conventions

**Files:**
- React components: PascalCase, `.tsx` (e.g., `CharacterPool.tsx`, `AuthProvider.tsx`)
- Hooks: camelCase with `use` prefix, `.ts` (e.g., `useDraftState.ts`, `useAuth.ts`)
- Next.js pages: lowercase `page.tsx` (enforced by Next.js App Router)
- Next.js layouts: lowercase `layout.tsx`
- CSS Modules: `ComponentName.module.css` co-located with the component
- SpacetimeDB tables: PascalCase, `.ts` (e.g., `matchSession.ts`, `userIdentity.ts`)
- SpacetimeDB reducers: camelCase, grouped by domain in `.ts` files
- Generated bindings: snake_case filenames (e.g., `hsr_character_table.ts`, `login_as_guest_reducer.ts`)

**Directories:**
- Feature directories: kebab-case (e.g., `admin-view`, `game-data`, `team-builder`)
- Next.js route groups: `(name)` convention, no URL segment
- Dynamic route segments: `[paramName]` (e.g., `[matchId]`)

## Key File Locations

**Entry Points:**
- `app/layout.tsx`: Root layout — all providers mounted here
- `app/providers.tsx`: All context providers composed here
- `spacetimedb/src/index.ts`: Backend module entry point

**Configuration:**
- `lib/spacetimedb.ts`: SpacetimeDB client connection constants
- `lib/spacetimedb-server.ts`: Server-side SpacetimeDB singleton
- `app/api/auth/authOptions.ts`: NextAuth Discord OAuth config
- `spacetime.json`: SpacetimeDB CLI publish target (maincloud)
- `tsconfig.json`: TypeScript path alias `@/` maps to project root

**Core Logic:**
- `src/module_bindings/index.ts`: All generated table and reducer accessors
- `spacetimedb/src/schema.ts`: Full database schema definition
- `components/features/auth/hooks/useAuth.ts`: Authentication state machine
- `components/features/game-data/components/GameDataProvider.tsx`: Game data subscriptions
- `components/features/types/enums.ts`: Shared frontend type definitions

**Testing:**
- Not detected — no test files or test configuration found

## Where to Add New Code

**New Backend Table:**
1. Define table in `spacetimedb/src/tables/<tableName>.ts`
2. Import and add to `spacetimedb/src/schema.ts`
3. Run `spacetime publish` then `spacetime generate`
4. Generated binding appears in `src/module_bindings/`

**New Backend Reducer:**
1. Add reducer function to the relevant domain file in `spacetimedb/src/reducers/`
2. Export from `spacetimedb/src/index.ts`
3. Run `spacetime publish` then `spacetime generate`
4. Call via `conn.reducers.<reducerName>(args)` in client hooks

**New Frontend Feature:**
- Implementation: `components/features/<feature-name>/`
  - Components: `components/features/<feature-name>/components/`
  - Hooks: `components/features/<feature-name>/hooks/`
- Page route: `app/(<group>)/<route-name>/page.tsx`

**New Shared UI Component:**
- Implementation: `components/globals/<category>/ComponentName.tsx`

**New Shared Hook (cross-feature):**
- Implementation: `components/features/hooks/useHookName.ts`

**New Utilities (non-React):**
- Implementation: `lib/<utilityName>.ts`

**New Admin Script:**
- Implementation: `scripts/<scriptName>.ts` (run via `npx tsx scripts/<scriptName>.ts`)
